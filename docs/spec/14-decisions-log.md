# Decisions log

This log lists every decision of the twelve subsystem tabs in one line, with its reason and its round 2 status; each tab still owns its decisions, their full text and the alternatives it rejected. It holds 380 decisions: ING 25, ANV 31, FLX 38, COV 23, KLN 44, MEC 30, MFG 29, ELX 26, AGT 32, UIX 30, ECO 32 and PLT 40. Round 2 revised 150 of them and added 100, and the other 130 stand as first drafted.

## Ingot language (ING)

From [Ingot language](01-ingot.md): 25 decisions, of which round 2 revised 10 and added 6.

| Id | Decision | Why | Round 2 |
| --- | --- | --- | --- |
| D-ING-1 | Ingot is pure, strict and expression-oriented, with immutable values, inference inside bodies and required signatures on every named function, feature and record. | Signatures let each module type-check alone, bounding recompilation to it and its dependents, and they generate dialogs and documentation. | |
| D-ING-2 | Every dimensional literal carries its unit, no file or package declares a default unit, and SI conversion is exact rational arithmetic with one correct rounding. | A default unit makes a bare number mean different things in different files, and exact conversion makes `25.4mm == 1in` hold bit for bit. | |
| D-ING-3 | Plane angle is a base dimension never cancelled implicitly; torque is J/rad, inertia kg·m²/rad², rotational stiffness J/rad², oscillation angular frequency T⁻¹. | With torque in N·m the laws of rotation each carried a stray radian (R3-29), and rad/s would put one into ωL. | revised |
| D-ING-4 | A `Tol<T>` is accepted wherever `T` is declared; the slot holds the nominal plus a tolerance-site reference, and feature calls record their tolerances. | It keeps contract section 6's `thickness: Length = 4mm ± 0.1mm`, carries the tolerance to the call that realizes it as PMI, and keeps geometry at nominal. | |
| D-ING-5 | `Tol` arithmetic uses affine forms over per-site noise symbols: worst case by default, exact for linear stacks, statistical only through explicit calls. | Linear stacks must be exact and repeated dimensions correlated, while two spacers cut from one specification are two characteristics (R3-30). | revised |
| D-ING-6 | GD&T controls are records from dialect-specific functions; legality rules are trait bounds where the aspect kind is static, else build-time checks. | The commonest GD&T errors (material modifiers on surfaces, deleted symbols, mixed dialects) become compile errors at their line. | |
| D-ING-7 | Approximate comparisons return a three-valued `Truth` decided only by disjoint enclosures; branching on `Undecided` waits as `Pending` and fails with `ING6401` at the fidelity ceiling. | Four tabs had four rules (R3-07), comparing estimates passes designs within numerical error, and waiting spares branches evaluated at `Interactive` (R3-14). | revised |
| D-ING-8 | Queries are values of named arguments resolved by an `anvil::resolve` node, with certified declarative filters, anchored rank selectors and explicit `where:` closures. | Declarative filters can be certified, cached and explained, and anchored ranks cannot silently swap winners within declared ranges (R2-22). | revised |
| D-ING-9 | Constraints, analytic Field expressions and weak forms are one mechanism: staged symbolic values built by ordinary functions and handed over as a hash-consed expression DAG. | One mechanism serves MEC's constraints, FLX's constitutive functions and analytic Fields, and equal expressions become equal keys. | revised |
| D-ING-10 | Ingot has no user-visible effect system: operations are pure calls, and checks, notes, tolerance sites and PMI are write-only accumulators ordered by call site. | Effect annotations would describe effects the language forbids, and canonical order makes accumulators independent of evaluation order. | |
| D-ING-11 | Deterministic failures propagate to the nearest `try` or feature boundary and are cached there; `try` converts them into `Result`, and no construct observes Aborts. | A `?` on every geometry call adds noise, and a fallback taken because a worker ran out of memory would be cached as geometry (R3-03). | revised |
| D-ING-12 | Checks are declarations evaluated as their own nodes: a failing or undecided check never stops geometry, and a feature cannot branch on a check's outcome. | Designers need to see failing geometry, expensive predicates run later at lower priority, and adding a check never changes a design or a solve. | |
| D-ING-13 | Until `ingot-bench` shows Ingot above 2% of a golden-product rebuild, the reference interpreter is the only executor; a Wasm code generator follows, phase 2 earliest. | Phase 1's golden products need only orchestration speed, which an interpreter reaches, and a second executor would sit on the critical path (R6-25). | revised |
| D-ING-14 | Plain values use reference counting with in-place update of uniquely referenced lists and records: Rust reference counts in the interpreter, Perceus in the code generator. | Immutable strict values form acyclic graphs, so no cycle collector is needed, and prompt freeing keeps loops within the semantic memory limit. | revised |
| D-ING-15 | The Rust fallback is `#[ingot::feature]`, generating the WIT world, `wit-bindgen` glue and a typed Ingot wrapper; operation calls go through the WIT package `crucible:ops`. | One signature carries units and ranges to the type checker and dialogs, so a Rust feature looks like an Ingot one. | revised |
| D-ING-16 | The lockfile pins a language behavior version beside the operation versions, and a toolchain implements every language behavior version in its support window. | An old design must rebuild identically, and fuel costs and std numerics are part of its result. | |
| D-ING-17 | Dialogs are generated from feature signatures, types, doc comments and a small attribute vocabulary, with conditional visibility as pure closures; there is no dialog language. | One declaration serves the dialog, docs, semantic-version checks and agent tool schemas, so they cannot drift. | |
| D-ING-18 | The grammar suits structural editing: newline-terminated statements, one statement per block, comments owned by the next block, set-merging named arguments, block-local parsing. | The live document needs a block per unit of concurrent work and an owner for every byte, and file-level recovery re-associated blocks (R3-32). | revised |
| D-ING-19 | Crucible builds Ingot from scratch rather than forking KCL's MIT-licensed implementation, and studies KCL's tests and documentation as references, with attribution. | Most of what matters is new, from rational dimensions to text-derived sites, and `kcl-lib` couples execution to an engine connection. | |
| D-ING-20 | Quantities have four flavors under one trait, `Scalar<D>`; quantity parameters accept every flavor at every call position with one meaning, and `Exact<D>` opts out. | Round 1 lifted flavors by position-specific rules, so `rect(other.edge(…).length(), 10mm)` failed and plain functions rejected symbolic values (R3-31). | new |
| D-ING-21 | `OpSite`s derive from source text: frames carrying a statement identity from binding names, a call identity from callee and occurrence, and iteration keys. | Block ids changed after a Git round trip, a retyped statement or publication (R3-06, R2-02), and slot paths renamed stages on append (R2-06). | new |
| D-ING-22 | Variant parameters are ordinary parameters marked `#[configuration]`, and an Instance's existence may depend only on them and on constants, checked at compile time. | The 150% BOM needs a static account of which Instances exist under which options, and plain `if` let existence follow geometry (R3-18). | new |
| D-ING-23 | Per-call limits come from source and manifest only and enter the node key; evaluation-wide limits and policy ceilings act only as Aborts. | A policy-clamped limit made organizations cache different results for one key (R3-12), and per-call limits alone allowed unbounded self-calling chains (R3-04). | new |
| D-ING-24 | The syntax tree classifies every span as free text or structure, and merging endorses only structure. | An agent could address a later reader through a merged comment, identifier or description template (R5-02). | new |
| D-ING-25 | In phase 1 the language service ships in Crucible and as a stdio LSP server, with VS Code and Zed extensions and a viewport-driving request. | Code-CAD users already work in those editors, and an in-app editor alone would have to compete with them as a product (R6-23). | new |

## Anvil geometry kernel (ANV)

From [Anvil geometry kernel](02-anvil.md): 31 decisions, of which round 2 revised 12 and added 8.

| Id | Decision | Why | Round 2 |
| --- | --- | --- | --- |
| D-ANV-1 | Anvil has six crates, `anvil-geom` → `anvil-topo` → `anvil-planar` → `anvil-mesh` → `anvil-implicit` → `anvil-ops`, above `base`, `field` and `kernels`, all `forbid(unsafe_code)`. | Contract 12 places `base`, `field` and `kernels` below Anvil and confines `unsafe`, and cages share the mesh half-edge structure. | revised |
| D-ANV-2 | Mixed operations return the least lattice representation (Mesh ⊂ BRep, SubD ⊂ BRep, BRep ⊂ Implicit) holding both operands exactly, keeping surviving B-rep faces. | Exact faces keep their names and attributes, and any later conversion is explicit and bounded. | revised |
| D-ANV-3 | Resolution is per Body and scale-relative, 2⁻³⁰ of the box diagonal rounded to a power of two, with frames on a fixed 2⁻²⁰ m grid. | Nanometres to hundreds of metres need scale-relative tolerances, a fixed value is coarse for MEMS and wasteful for ships, and powers of two scale exactly. | |
| D-ANV-4 | Linear decisions use exact predicates; curved ones use certified enclosures under the three-way rule, decided in rounds against frozen tolerances with capped growth. | Exact algebraic predicates on NURBS, offset and blend geometry are impractical, and frozen tolerances make outcomes independent of pair order and thread count. | revised |
| D-ANV-5 | Anvil generates its own linear and indirect predicates, porting Shewchuk's method and Attene's scheme. | Safe Rust in canonical order runs identically in native and Wasm builds, and indirect predicates make mesh arrangements exact without rational coordinates. | |
| D-ANV-6 | One cellular B-rep (regions, shells, two-sided faces, loops, coedges with radial cycles, edges, vertices) serves every B-rep Body, with material per region. | Multi-material parts, conformal meshing and Booleans that keep interfaces all need faces shared by regions. | |
| D-ANV-7 | Offset, intersection, sweep, blend, helix and subdivision-limit geometry stays procedural with a certified cached NURBS approximation, and nesting stops at depth three per face. | Procedural geometry does not accumulate approximation error across features, and the depth limit bounds cost and enclosure width on blend-heavy parts. | revised |
| D-ANV-8 | B-rep face geometry is always parametric; implicit surfaces never appear as B-rep faces. | Trimming, tessellation, blending and export rely on (u, v) domains, and implicit operands already yield implicit Bodies. | |
| D-ANV-9 | The encoding is canonical: geometry and name parts, content-defined leaves and Merkle hashes, invariant across minor versions and readable for every major version. | The two identities need a separable name part, builders on different releases must agree on one `OpKey`, and hashing stays proportional to edits. | revised |
| D-ANV-10 | Implicit nodes carry a statically propagated distance kind and Lipschitz constant, and operations that need exact distances redistance in a narrow band. | Lattices, smooth blends and warps rarely give exact distances, and Lipschitz pruning relies on the same property. | |
| D-ANV-11 | Implicit tapes are kernel-IR programs: a pruning SIMD interpreter is the canonical CPU evaluator, compiled paths match its bits, and a WGSL interpreter serves previews. | Compilation gains about 25% once pruning runs, one IR keeps operation order fixed, and tapes as data avoid a shader compile per edit. | revised |
| D-ANV-12 | Volume meshing, adaptation and node optimization are Anvil operations; Flux chooses what to mesh and how finely through sizing and metric Fields. | Meshing needs exact geometry, the same predicates and tolerance model, and `EntityId`s, and its outputs are Bodies other operations consume. | |
| D-ANV-13 | Anvil implements Catmull-Clark subdivision with semi-sharp creases natively in Rust, following OpenSubdiv's rules and using OpenSubdiv as an oracle. | Limit surfaces must evaluate identically on CPU and in Wasm and feed exact B-rep faces. | |
| D-ANV-14 | `EntityId`s hash the text-derived `OpSite`, role, generating ids and discriminator, excluding argument values; names never feed geometric computation. | Dimension edits must not rename entities, and text-derived identities survive Git round trips and publication. | revised |
| D-ANV-15 | Resolution walks recorded lineage, then certified filters; splits, deletions and ambiguity are typed errors, and merges resolve with a note only for surface use. | Contract 5 forbids silent re-selection, and a merged face keeps a sketch plane's surface but changes the extent a fillet or GD&T target means. | revised |
| D-ANV-16 | SSI uses Bernstein and interval subdivision, normal-cone loop exclusion, Krawczyk-certified characteristic points and certified tracing, with a topology certificate per pair. | It gives branch-graph guarantees in `f64` with interval rules, parallel over pairs. | |
| D-ANV-17 | In intersections the GPU only orders and prunes CPU work; every intersection point is a certified root of the exact equations, never a thresholded sample. | Outputs are identical with and without a GPU, certified roots carry guarantees thresholded samples cannot, and counsel assesses this distinction. | revised |
| D-ANV-18 | Each operation version and every internal module it uses (for example `ssi@4`) is frozen by source hash once released; changes go into new module versions. | Frozen source plus PLT's reproducible toolchain rebuilds old designs by construction, which no regression corpus can promise. | |
| D-ANV-19 | One cellular arrangement engine implements Booleans for every representation pair without an implicit operand, and serves n-ary expressions, `split`, `imprint` and `interference`. | These operations differ only in which cells they keep and report, and Parasolid's Booleans already imprint, join and select. | |
| D-ANV-20 | A phase 0 bake-off chooses the mesh Boolean method among ρ-grid integer local arrangements, topological aggregation and indirect predicates, with one rounding per CSG tree. | Published speeds differ by one to three orders of magnitude, and ρ-grid quantization keeps Anvil's resolution. | revised |
| D-ANV-21 | Lattice inclusions are exact; approximating conversions record per-face `{ position, normal }` bounds propagated with certified conditioning, or become `NotQuantified`. | A Hausdorff bound says nothing about normals, so operations on approximated faces could otherwise report `Guaranteed` bounds that do not hold. | revised |
| D-ANV-22 | Anvil parallelizes by data-defined decomposition with canonical merge order, fixed reduction trees and geometric independent-set priorities. | Results are bit-identical for any thread count, without locks around floating-point state. | revised |
| D-ANV-23 | Anvil is native Rust and links no external geometry kernel; OCCT, Manifold, Geogram, OpenSubdiv, fTetWild, libfive and Axom serve only as differential oracles and benchmarks. | The core must be Rust, free of GPL linking, identical in native and Wasm builds and frozen per version, which C++ dependencies cannot guarantee. | |
| D-ANV-24 | Bodies carry a `GeometryId` beside the `ObjectId`, and naming operations split into a geometric stage keyed by `GeometryId`s and an `OpSite`-keyed relabeling stage. | Names hash upstream sites transitively, so one named identity would defeat cross-design caching, early cutoff after refactors and approvals over geometry. | new |
| D-ANV-25 | Anvil is label-invariant: orders, perturbation indices, priorities and seeds come from geometry, topology and arguments, so renaming `EntityId`s and `OpSite`s changes only name sections. | Geometry must follow from source text alone, so Git round trips and published packages rebuild bit-identically (contract 7.1). | new |
| D-ANV-26 | Constructions record `Continuity` certificates on edges they make tangent, and tangential contact along curves uses a certified contact-curve algorithm. | Blend tangency is the common case, the full system is singular along contact curves, and certificates keep tangency the construction already knows. | new |
| D-ANV-27 | `anvil-planar` decides exactly on stored integer geometry, snaps constructions conservatively in a declared direction, and keeps an arc only if it passes the exact check. | Offsets and arc intersections leave the integer grid, and rounding to nearest could place a fill about 0.7 grid units too close, failing Crucible's own exact checks. | new |
| D-ANV-28 | Anvil maps `Preview`, `Interactive` and `SignOff` to surrogates, validated floating-point decisions and certified decisions. | Certified decisions cost time drags and early rebuilds cannot spend, validation keeps `Interactive` Bodies valid, and `SignOff` keeps releases certified. | new |
| D-ANV-29 | One re-fillet benchmark on a phase 0 ABC corpus measures blends: 95% success on stage-1 configurations at the phase 1 gate, 97% overall at phase 2. | Golden product 1 and everyday parts need sequential fillets, rolling overflow and mixed corners from the start, and one benchmark keeps ANV and MEC comparable. | new |
| D-ANV-30 | Placement keeps names; copying derives names from the source with role `copy` or `mirror`. | Otherwise `half + mirror(half, plane.yz)` and features over two Instances of one Part would put identical ids into one Boolean. | new |
| D-ANV-31 | Imported entities are named from source persistent ids, else from exact geometric and adjacency signatures, never ordinals; successive imports match into a reviewed `import_map`. | One rule serves Anvil and ECO, ordinals change when a supplier re-exports, and quantized signatures flip at quantization boundaries. | new |

| D-FLX-11 | `Portable` code computes elementary functions only with PLT's correctly rounded `detmath`; GPU kernels use fixed-sequence approximations with documented ulp bounds, never vendor built-ins. | Platform and vendor libraries differ, and correct rounding on GPUs needs precision WGSL cannot guarantee (R1-43). | revised |
| D-FLX-12 | Discretization is per region: slender shells and beams, immersed octree solids, fitted meshes at contact and boundary layers, homogenized lattices and isogeometric thin NURBS shells. | A volumetric octree on golden products 2, 4, 5 and 8 needs 10⁶ to 10⁸ DOFs where reduced models need 10⁴ to 10⁵ (R1-02). | revised |
| D-FLX-13 | One octree serves shifted boundary at `Interactive`, CutFEM at `SignOff` and finite cell for voxels; shifted boundary stays default only if it passes FLX-O-DISC-3. | Uniform cells suit GPUs within 1 s, while `SignOff` needs conditions on the true surface. | revised |
| D-FLX-14 | Surrogate predictions are `Estimated` Fields with marginal scope that may drive `Preview`, `Interactive` and exploration; `SignOff` needs a per-prediction bound or a confirming solve. | Split-conformal coverage is marginal, exact conditional guarantees need assumptions, and optimizers steer queries toward a surrogate's errors. | revised |
| D-FLX-15 | Flux produces budgets and ING decides checks by one rule, returning `base`'s `CheckOutcome`; Flux adds no margin rule. | Four tabs had four rules (R3-07). | revised |
| D-FLX-16 | Flux builds its own matrix-free p- and h-multigrid and deterministic AMG, with patch smoothers and aggregation around cut cells; hypre and PETSc are optional bridges. | AMG setup must coarsen identically in every class and run in Wasm, and cut cells defeat point smoothers (R1-17). | revised |
| D-FLX-17 | A GPU solve yields a pinned Field that `Portable` `flux::certify` re-checks in `CpuCanonical`; `f32` inner solves use defect correction with a canonical CPU fallback. | Metal and WebGPU lack `f64`, yet `SignOff` needs canonical outcomes everywhere, and defect correction stalls as κ(A)·u_f32 approaches 1 (R1-11). | revised |
| D-FLX-18 | GPU reductions use integer-only exact accumulation: bins of 32-bit limbs with explicit carries, combined in fixed order. | wgpu offers 64-bit integer atomic add only on Vulkan and DX12 and float atomics only on some devices, while 32-bit integer arithmetic is exact everywhere. | |
| D-FLX-19 | Canonical CPU solves, estimators and `flux::certify` are `Portable` in `CpuCanonical`; GPU solves are `ClassExact` in `Gpu(GpuClass)`, and their `SignOff` checks rest on `certify`. | Release gates need canonical outcomes, while GPUs pay off at `Interactive` and as solvers the CPU certifies. | revised |
| D-FLX-20 | Flux pins the resolved plan, not just the solver version: a versioned `flux::plan` resolves every default, and the resolved plan enters the cache key. | Most result drift comes from changed defaults, not changed algorithms. | |
| D-FLX-21 | Gradients are derivatives at a frozen discretization, and their bound says so; Taylor tests across discretization changes are flagged, and optimization uses smooth aggregation weights. | The discrete objective is not differentiable where the discretization changes with the design (R1-19). | revised |
| D-FLX-22 | Fields paint on true geometry: per-pixel WGSL where the GPU tier allows, else samples with stated error; probes sample exactly on the CPU. | Linear interpolation of high-order solutions misplaces peaks (D-UIX-13), and display work on the UI's device avoids a host-memory round trip (R6-16). | revised |
| D-FLX-23 | Peak and pointwise quantities are regularized goals (`f.max(over: R, smooth: ρ)`, `f.at(x, smooth: ρ)`, `pnorm` for optimization), with the regularization gap as an error part. | A raw maximum is not differentiable, so DWR cannot estimate it, and it diverges at singular points (contract section 7.1). | new |
| D-FLX-24 | Every `Estimated` bound is reported multiplied by its calibration factor η99 from pinned `std::sim::calibration` tables, and a problem class without an entry reports `Indicator`. | ING's single decision rule then works unchanged at `Interactive` and `SignOff` (R1-07, R3-07), and bounds never depend on the machine. | new |
| D-FLX-25 | Newton and arc-length solvers monitor the tangent's inertia and return `Bifurcation` at a sign change; a study picks a branch only explicitly in source. | Rounding decides which branch Newton follows, so a silent choice breaks cross-class agreement (principle 4, R1-13). | new |
| D-FLX-26 | Dimensional-reduction error is a model-form part, estimated by re-solving 3D patches around goal regions and otherwise `NotQuantified`, which makes a `Pass` there conditional. | Shell and beam theories carry modelling error that refinement never removes. | new |
| D-FLX-27 | Networks compile to index-1 DAEs by Pantelides reduction with static per-mode dummy derivatives, BLT ordering and tearing; states are re-selected only at deterministic events. | One structural analysis is invalid after a mode change (R1-50), and run-time state selection between events would make results depend on solver history. | new |
| D-FLX-28 | Multibody dynamics is an index-3 DAE on the Lie group of rigid motions, integrated by Lie group generalized-α with scaled constraints and rank-revealing QR. | No parameterization means no singular configurations, and the method is second-order in every unknown without index reduction. | new |
| D-FLX-29 | Cables and hoses are geometrically exact Cosserat rods sharing the multibody integrator, with Kirchhoff behaviour as the stiff-shear limit. | Hoses stretch and shear under pressure and clamping, and one integrator couples rods to joints and contact. | new |
| D-FLX-30 | Flux owns the FMI 3.0.2 and SSP 2.0.1 runtime; native-binary FMUs run as External Ops on untrusted-evaluation workers, Wasm FMUs as sandboxed Ops. | Native FMUs are untrusted code (contract section 7.8), and one runtime ends duplicate FMI specifications in FLX and ELX (R3-24). | new |
| D-FLX-31 | Explicit dynamics on cut cells needs ghost-penalty mass stabilization proven cut-independent; until FLX-O-DISC-7 confirms it, only fitted and isogeometric discretizations run it. | Lumped mass scales with the cut fraction while stiffness does not, so the critical step tends to zero (R1-21). | new |
| D-FLX-32 | Resonant and narrowband problems use frequency-domain Nédélec FEM with port eigenmodes, PML and an adaptive fast sweep with a residual bound; broadband and EMC use FDTD. | ELX requires Palace-level capability, which offers lumped and numeric wave ports and an adaptive fast sweep (R1-22). | new |
| D-FLX-33 | Navier–Stokes uses PCD or scaled least-squares commutators up to moderate Reynolds numbers, an augmented Lagrangian preconditioner at high ones, and dual splitting for high-order transients. | Pressure-mass Schur approximations suit only Stokes (R1-23), and the augmented Lagrangian needs about 3 Krylov iterations per Newton step at Re = 1,000. | new |
| D-FLX-34 | Methods without an a posteriori estimator report `Indicator` discretization bounds unless `std::sim::solution_verification` applies Roache's grid convergence index over three levels. | Code verification does not verify an application result, and `Indicator` bounds never support `SignOff` (R1-28). | new |
| D-FLX-35 | Propagating `Tol<T>` through physics is worst case by default, by adjoint linearization in `std::uq::worst_case`; statistical propagation is an explicit `std::uq::propagate` call. | One adjoint per goal, and one semantics for tolerances everywhere. | new |
| D-FLX-36 | `Portable` linear algebra runs on the canonical `linalg` crate (fixed blocking and lane order, no FMA, index tie-breaks); unmodified faer runs only in `CpuIsa`. | faer's dense kernels size blocks from detected caches and use FMA microkernels, so sums depend on the machine (R1-10, R6-21). | new |
| D-FLX-37 | During a geometric drag, physics shows as `Proxy` until the full update arrives (phases 1 and 2); from phase 3, reduced models answer through a morphing map. | Cell classification changes with geometry, so a reduced model on one discretization cannot serve geometric parameters without a morph (R1-16). | new |
| D-FLX-38 | Nested and phase-space models (particle diffusion, FE² micro problems, discrete ordinates, population balances) are forms over product spaces with a parameter measure `dξ`. | Battery cells (SPMe, DFN) and COV's radiation models then get form-level derivatives and GPU kernels (R1-24). | new |
