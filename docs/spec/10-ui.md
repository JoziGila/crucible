# UI and interaction (UIX)

Crucible's interface is a GPU-rendered view of one typed Ingot program, and it changes the product only through `api`. One Rust toolkit and one wgpu renderer give every Tier 1 platform the same features on three declared GPU tiers. Every result shows its status and error, review puts evidence before diffs, and agents work visibly on their own branches.

## Workspace and information architecture

**Decision D-UIX-1:** The UI holds no product state: product changes are `api` Edit or Propose calls, and personal views live outside Changes. *Why:* principle 2 and agent parity, while personal camera moves would flood history (R12-33). *Rejected:* feature records kept in the GUI (two sources of truth); camera and visibility in the model (noisy diffs and merges). (revised in round 3)

Every command records its `api` call, and "Copy as `api` call" hands any manual step to an agent or a script. The top bar shows the open design's label (level, controls and scopes), and every snapshot and export carries it.

### Model tree, dialogs and version history

The tree unifies structure and history: Assembly, Instances, Part, features and, on demand, the entities each feature created. Top-level nodes add Parameters, Studies, Setups, Checks, Saved views and Packages.

- **Rows** show type, name, status glyph, Instance count and presence, never by color alone. The tree virtualizes 1,000,000 nodes and filters by name, type, status or `Query`.
- **Edits.** Rename writes `#[was(old_name)]`, so `CallSite`s survive. Delete previews dependents, and reorder refuses illegal moves with the reason ("`web` uses `base`, defined on line 4").
- **Rollback marker.** Dragging it shows the Part as evaluated up to a feature, and edits made there insert at that position.

The *feature list* orders program statements; the *version history* orders Changes in time. The UI never calls both "history".

Feature dialogs are generated from Ingot `Feature` metadata: typed fields with units and ranges, `Tol<T>` inputs, enumerations, and selection fields that show the readable `Query`. Typing `=` makes any field an expression. Dialogs are modeless: edits preview through literal overrides, Done writes one Change, and Cancel writes nothing.

Properties show exact measurements from Anvil (area, length, radius, mass properties with the Material), never values from display meshes. The version history groups Changes by session and author, people and agents alike. An entry renders read-only, two entries open the review diff, and Restore writes a new Change.

### Result status, checks and errors

Every displayed Body, Field, metric and check carries the contract's `ResultStatus`. The quiet default is `Ready` at or above the fidelity the view or check declares; a lower fidelity shows the derived "provisional" badge (contract 5).

| --- | --- | --- |

| --- | --- | --- |

## UI toolkit

Crucible needs a Rust toolkit that draws on the GPU, shapes every script and virtualizes million-row trees. It must also expose a full accessibility tree on every Tier 1 platform and handle input method editors (IME). No surveyed toolkit does all of this:

| Option | Gap for Crucible |
| --- | --- |
| GPUI | Tied to Zed, with no documented browser target; Narrator could not read it in a 2025 Windows test |
| egui | Its README documents AccessKit on Windows and macOS only |
| Masonry | Paints through Vello and wgpu; its README names backends for winit and Android, not the web |
| Slint | A second UI language |
| Webview shells | A second runtime |

**Decision D-UIX-3:** Crucible builds its own retained-mode GPU toolkit in the style of GPUI, on Taffy, Parley, AccessKit and wgpu, decided now. *Why:* Masonry lacks a non-compute paint path for G3 and a browser target, and closing both gaps is the own toolkit's renderer work (R12-08). *Rejected:* Masonry (no G3 path, no web backend); GPUI (tied to Zed); egui (no web accessibility); a bake-off whose fallback was fixed in advance. (revised in round 3)

Chain C (contract 13.2) starts with a risk spike on the toolkit's three hardest parts, named in the capability table below. If a part misses its oracle, Chain C is re-planned and the toolkit choice stands.

### Architecture

Interface state lives in typed cells (`State<T>`), and product data enters them only through `api` subscriptions. A widget's `render` builds keyed elements, Taffy lays out realized rows, and elements emit quads, glyph runs, icons, paths and viewport surfaces.

These batch into instanced wgpu draws without compute, identical on WebGPU and WebGL2, and frames render only on input, state change, animation or refinement. Other paths tessellate on the CPU, since Vello's original renderer needs compute. Vello Hybrid, "roughly beta quality" in April 2026, is re-evaluated at the phase 2 gate.

### Text and accessibility

- **Shaping.** Parley shapes with HarfRust, a Rust port of HarfBuzz that "for the most part passes the HarfBuzz test and fuzzing suites". ICU4X resolves bidi.
- **Fonts.** Inter sets interface text and JetBrains Mono code. Noto covers "more than 1,000 languages and over 150 writing systems", and system fonts are only a logged last fallback.
- **Rasterization.** Skrifa loads, scales and hints outlines into an alpha atlas at four subpixel offsets. Editors handle bidi carets, grapheme deletion, IME composition and platform shortcuts.

**Decision D-UIX-4:** Grayscale antialiasing with bundled fonts everywhere, hinted by Skrifa below UI scale 1.5 and unhinted above, with the same code on every OS. *Why:* identical layout and bitmaps for snapshot oracles, correct rendering over translucent surfaces, and crisp 11 and 12 px text on 1080p displays (R6-43). *Rejected:* each OS's text stack (metric differences); LCD subpixel antialiasing (fails over transparency); unhinted text everywhere (soft beside native applications). (revised in round 2)

AccessKit adapters provide UI Automation, NSAccessibility and AT-SPI, plus Android for tablets; iPadOS runs the web build. Its web adapter is planned, not released, so Crucible builds it upstream (D-PLT-8): a hidden DOM mirror with ARIA roles, names, states and bounds, as in Flutter web.

Virtualization bounds the mirror to about 2,000 realized nodes at under 1 ms per frame (target), and collections expose `aria-setsize` and `aria-posinset`.

**Decision D-UIX-5:** Crucible implements the AccessKit web adapter as a DOM mirror and enables it by default on the web. *Why:* WCAG 2.2 AA on a Tier 1 platform, with no hidden opt-in step. *Rejected:* a DOM-based web UI (breaks the single toolkit); Flutter-style opt-in (users must first find a hidden control).

Browsers use the EditContext API where available, so a custom-rendered editor receives IME composition and reports caret bounds. EditContext is not Baseline; elsewhere a hidden `<textarea>` proxy sits at the caret, and both paths feed one input stream.

The toolkit's platform needs are PLT's services, listed under Interfaces. PLT's dependency register tracks Taffy, Parley, HarfRust, Skrifa, AccessKit, winit and wgpu, each with a fork plan (R6-30).

## Renderer

The renderer is one crate, `apps/renderer`, on wgpu 30. It draws the viewport, Field views, toolpaths, 2D canvases, overlays and headless snapshots on the toolkit's wgpu device.

### GPU capability tiers

wgpu 30 exposes 64-bit atomic min and max (`SHADER_INT64_ATOMIC_MIN_MAX`, `TEXTURE_INT64_ATOMIC`) and indirect-count draws on native backends only. The WebGPU Candidate Recommendation Draft of 15 September 2026 has no multi-draw indirect, bindless resources or mesh shaders, and WebGL2 has no compute.

| Tier | Where | Required capabilities | Capacity at 60 fps (contract 13.3 targets, by phase) |
| --- | --- | --- | --- |
| G1 Full | Native Vulkan 1.3, DX12 Shader Model 6.6, Metal 3.1 | Compute, storage buffers, indirect draws | 5M visible triangles (1); 100,000 Instances (2); 1,000,000 Instances on the high band (4) |
| G2 Compute | WebGPU with `core-features-and-limits`; native adapters below G1 | Compute, storage buffers, single indirect draws | 2M visible triangles, or 30 fps at 5M (1); 20,000 Instances (2) |
| G3 Raster | WebGL2, GLES 3.0, WebGPU compatibility mode | Instanced draws, float render targets | 30 fps at 2M visible triangles (1); 10,000 Instances of at most 1,000 distinct Parts (2) |

Compute rasterization is a reported G1 capability, `compute_raster`, present when the adapter exposes wgpu's 64-bit atomic features. M1-series Macs lack it (Platform notes), and a G1 adapter without it declares a measured capacity in the graphics popover (CCR-UIX-8). In phase 1, the forward renderer's Instance capacity per tier is a measured target that blocks nothing (contract 13.3).

**Decision D-UIX-6:** Every feature works on every tier; tiers differ only in declared capacity and refinement speed, which the graphics popover names. *Why:* the contract's identical-features rule, stated honestly, since hardware cannot deliver identical scale. *Rejected:* hiding features on weaker tiers (breaks parity); one lowest-common-denominator renderer (wastes native hardware by an order of magnitude).

Every GPU path has a CPU path, and servers render through software Vulkan (Mesa lavapipe) or WARP. PLT's safe mode gets the G3 path, and after device loss the renderer rebuilds from cached packages, typically within one second.

### Display data

Anvil owns tessellation (`anvil::tessellate`) and, from phase 2, the cluster DAG (`anvil::cluster_dag`); the renderer never tessellates B-rep.

```rust
/// Produced by Anvil, cached in CAS, keyed by GeometryId and tolerance; layout fixed by ANV and UIX.
pub struct DisplayPackage {
    pub geometry: GeometryId,            // name-free: shared by every design with equal geometry
    pub status: ResultStatus,            // Ready(Preview) while streaming, then the requested fidelity
    pub chordal_error: Length,           // max distance from display triangles to the Body, edge tolerance included
    pub bounds: Aabb,
    pub edges: Vec<DisplayEdge>,         // polyline per model edge, with canonical edge number and continuity
    pub pages: Vec<ObjectId>,            // cluster pages, 64 KiB each; triangles carry canonical face numbers
    pub root_pages: Vec<u32>,            // always resident
}
```

- **Names join late.** Packages carry canonical entity numbers only. The renderer maps them to `EntityId`s through the Body's name table, keyed by the Body's `ObjectId`. Two designs with equal geometry therefore share pages, and each pick returns its own design's `EntityId`s (R8-18).
- **Watertight.** Anvil tessellates each edge once and shares its vertices with both faces, so healed imports stay watertight (ANV, R8-29).
- **Clusters** hold up to 128 triangles, and level-0 clusters never cross a face, so picking and updates work per face. Pages use meshoptimizer's codecs, and `anvil::cluster_dag` builds the DAG with its `clusterlod` method and monotone error bounds.
- **Updates.** An edit re-tessellates only changed faces, and refinement continues until chordal error projects under 0.5 px (target). DAG pages keep the level-0 layout.

**Decision D-UIX-7:** Each Body's display data is a clustered `DisplayPackage` cached in CAS, and culling, LOD and selection run locally. *Why:* interaction never waits for the engine, unchanged Bodies cost nothing after an edit, and one format serves desktop, browser, review and CI. *Rejected:* one mesh per Body (no LOD, full re-upload per edit); server-side video streaming (latency, bandwidth, no offline use). (revised in round 2)

The scene is a flat table of draw Instances mirroring the Assembly tree. Each has an `f64` transform, visibility, style and selection flags, and identical Parts share one package. On the GPU each translation is a high and low `f32` pair, and shaders subtract the eye position in the same split form.

**Decision D-UIX-8:** Every tier uses reversed-Z float depth, an infinite far plane and relative-to-eye split-precision transforms. The near plane sits at 0.1 times the distance to the nearest visible bound, down to 1 µm. *Why:* scenes span micrometre details and hundred-metre extents, and Reed found reversed-Z float depth gave "a *zero error rate*" in his test. *Rejected:* logarithmic depth (disables early depth test); per-frame CPU rebasing (costly at a million Instances).

### Two pipelines

**Decision D-UIX-24:** Phase 1 ships one forward renderer on every tier, with id targets for picking, model edges, per-Part discrete LOD over level-0 clusters, weighted blended transparency and section caps. *Why:* both phase 1 golden products are single Parts, and the open cluster-DAG implementation on wgpu was unfinished in March 2025 (R6-24). *Rejected:* the visibility-buffer pipeline in phases 0 and 1 (a long chain that GP1 and GP2 do not need).

From phase 2, G1 and G2 cull on the GPU against the frustum and last frame's depth pyramid. A cluster draws when its error projects under τ (1 px) and its parent's does not. The cut is crack-free, as in Nanite, with on-screen error under 1.5 px (target).

Clusters raster into a visibility buffer: packed depth and id through 64-bit atomics where G1 reports `compute_raster`, and `R32Uint` with hardware depth elsewhere. A second pass draws newly visible clusters, and a resolve pass shades from triangle ids.

On G2, culling compacts surviving triangle indices into one index buffer for one `drawIndexedIndirect`, reusing vertices and issuing no degenerate triangles (R6-46). Per-cluster `drawIndirect` with padding is the fallback where that buffer would exceed the binding limit. Where G1 reports `compute_raster`, clusters of sub-two-pixel triangles rasterize in compute, as Bevy's virtual geometry does on wgpu.

**Decision D-UIX-9:** From phase 2, G1 and G2 draw through a cluster DAG, two-pass GPU occlusion and a visibility buffer; compute rasterization needs `compute_raster`, and mesh shaders wait for phase 4. *Why:* Nanite, GPU-driven culling (Haar and Aaltonen 2015), niagara and Bevy, mapped onto WebGPU core; mesh shaders would add a G1-only path (R12-33). *Rejected:* G2 compute rasterization before stable Chrome, Firefox and Safari ship 64-bit atomic min and max; per-object draws everywhere (CPU-bound beyond about 10,000 Instances). (revised in round 3)

### Large assemblies and picking

- **Instancing.** A fastener used 40,000 times stores one package and 40,000 transforms of 64 bytes. A binned-SAH BVH over Instances is rebuilt when the Assembly changes and refit when Instances move.
- **Streaming (phase 2).** Clusters request pages each frame into a fixed pool with least-recently-used eviction. Native G1 pools default to 1 GiB, at most half of VRAM, and browsers follow PLT's memory table.
- **Coarse first (phase 2).** Root pages load first, meeting contract 13.3's 1,000-part row (coarse view in 2 s, full in 10 s). Sub-pixel Instances draw as points, and lightweight mode measures with "≈" until Anvil returns exact values.

A click reads the id target (phase 1) or the visibility buffer (phase 2) within contract 13.3's selection row. The triangle's canonical face number maps to the design's `EntityId` through the name table. A hit from a coarse cluster or within a pixel of an edge is confirmed by a CPU ray cast in under 2 ms (target).

G3 picks by CPU ray cast, avoiding WebGL2 readback stalls. Edges and vertices use a pick buffer widened to 4 px for mouse and 12 px for touch. Clicking again cycles stacked entities, and box selection follows CAD's enclosed and crossing convention.

Every selection becomes a `Query` before an edit uses it. `api` Inspect returns ranked candidates such as `base.face(role: end_cap)`, each with a robustness rating. Fragile ones carry `ING-L-FragileSelector` and a "Name this selection" fix.

**Decision D-UIX-10:** Picking reads an id target or the visibility buffer and confirms ambiguous hits on level-0 geometry; edits take selections only as ranked `Query` suggestions. *Why:* a fast pick that is never wrong about identity, and selections that survive rebuilds. *Rejected:* CPU-only ray casting (slow at assembly scale); raw `EntityId`s in source (unreadable). (revised in round 2)

### Edges, transparency and sections

Model edges come from the package, drawn as screen-space quads 1.25 px wide with analytic antialiasing; tangent joins draw thinner. Silhouettes of curved faces come from id, depth and normal discontinuities, and hidden lines dash in screen space so dashes never crawl. Drawings use Anvil's exact silhouette curves instead, following Bénard and Hertzmann's survey of the trade-offs.

**Decision D-UIX-11:** Phase 1 uses weighted blended transparency (McGuire and Bavoil); from phase 2, G1 and G2 resolve the nearest k layers exactly in a k-buffer of packed keys. *Why:* X-ray views of nested housings need exact front layers, and depth-only keys flicker on coincident mating faces (R6-27). *Rejected:* depth peeling (a geometry pass per layer); linked lists (unbounded memory); a fixed k (exceeds WebGPU's default 128 MiB binding above about 3.3 MP). (revised in round 2)

Each 32-bit key holds 24 bits of quantized reversed-Z depth and 8 bits hashing Instance and face. The resolve breaks remaining ties by Instance index and canonical face number, and k follows the adapter's `maxStorageBufferBindingSize` and the render resolution each frame. Display opacities clamp to 0.2 to 0.9, where weighted blending is tuned, and the graphics popover counts pixels whose layers exceeded k.

Sections take up to six planes or one box, each optionally locked to a face by `Query`. Caps draw where the nearest surface behind the plane is a back face of a closed Body. They are hatched per Material class and show the active Field in Simulate.

When the view settles, Anvil's exact section replaces the caps and supplies area, centroid and second moments.

### Styles, appearance and color

Engineering styles use a headlight with hemisphere ambient, so shading never hides geometry.

- **Appearance.** OpenPBR Surface 1.1.1 in a reduced real-time form with documented deviation, checked against MaterialX references. A `Neutral` appearance drops imported textures and is the default for agent renders (R5-17).
- **Ambient occlusion.** Ground-truth AO (Jimenez et al. 2016, ported from XeGTAO) runs at half resolution in motion. XeGTAO reports about 2.39 ms at 1080p on an Intel i7-1195G7 integrated GPU.
- **Color.** Rendering is linear Rec.709 in 16-bit float targets, output as sRGB, Display P3, or extended range for Realistic views on HDR displays. Khronos PBR Neutral tone-maps only the Realistic style, and lighting scales Field colors only within [0.8, 1.0].
- **Ray tracing.** A path-traced Realistic preview arrives in phase 5, since wgpu's ray queries are experimental.

### Anti-aliasing, render scale and implicits

In motion, edges and overlays use analytic antialiasing and surfaces a one-frame morphological filter on id and depth. When the camera stops, the renderer accumulates 16 jittered frames over about 270 ms at 60 Hz, then stops.

**Decision D-UIX-12:** No temporal anti-aliasing during interaction; progressive supersampling when the view is still. *Why:* engineers judge edges and small features during orbit, and temporal reprojection smears thin lines. *Rejected:* TAA (ghosting, history-dependent images); MSAA on the visibility buffer (four times the memory).

**Decision D-UIX-25:** In motion the 3D view renders at most 2.1 MP and upsamples; edges, overlays, text and still frames stay at native resolution. *Why:* pixel-proportional stages cost about 2.8 times more on a 5.9 MP panel, so 60 fps would fail before geometry is counted (R6-10). *Rejected:* native resolution in motion (misses 60 fps on mid-band laptops); downscaled edges and text (blurs what people judge).

BRep and Mesh Bodies draw from clusters; SubD Bodies show Anvil's limit surface, with the control cage while editing. Implicit Bodies draw from Anvil meshes at display tolerance. On G1 and G2 they evaluate directly per screen tile instead, with interval pruning, following Keeter's massively parallel method.

During edits this runs Anvil's WGSL tape interpreter, which takes tapes as data, so no pipeline compiles inside a drag (R6-42). A specialized shader compiles only for still views.

### Frame budgets

Targets on the reference laptop. Pixel-proportional rows are per render megapixel, so they hold on any panel under D-UIX-25, and GPU timestamps measure each stage.

| Stage | Budget (target) |
| --- | --- |
| UI input, state, layout, paint (UI thread) | 3.0 ms |
| Scene deltas, uploads, encoding (render thread) | 2.5 ms |
| Instance culling; cluster culling and LOD cut (GPU) | Measured per tier in phase 2, then fixed |
| Raster and depth pyramid, 5M visible triangles (GPU) | 6.0 ms |
| Resolve and edges; AO, transparency and overlays (GPU) | 1.2 ms and 1.2 ms per render MP |
| Tone map, filter, composite (GPU) | 0.5 ms per native MP |
| GPU-computed display data reaching the UI device | 5 ms per 100 MB on unified-memory laptops |

Contract 13.3's orbit, X-ray and input-to-photon rows apply, and the X-ray row includes the k-buffer's second pass. Engine dispatches follow PLT's rule of 4 ms while any window renders interactively. Display-only GPU work runs on the UI process's device, and idle windows issue zero submissions.

### Snapshots

`inspect.render` (AGT's method) dispatches to `apps/headless-render`, a service that links this renderer, so `api` depends on neither. It renders a `ViewState` under a `RenderProfile` (contract 5).

**Decision D-UIX-26:** Snapshots are non-canonical: each carries `PlatformClass::Unverified`, the renderer identity and its `RenderProfile`, and never enters another node's key or an approval subject. *Why:* llvmpipe "uses LLVM to do runtime code generation" for the host CPU, macOS has no software renderer, and legends depend on locale and units (R6-26, R3-35). *Rejected:* byte identity across the canonical class (cannot hold); snapshots without a profile.

## Field views

Fields are painted on the true geometry, never exported to a separate post-processor. A `FieldView` in `ViewState` names a study result and how to show it.

```rust
pub struct FieldView {
    pub source: CallSite,                // the study call whose result is shown
    pub output: Symbol,                  // which result Field, such as von_mises
    pub quantity: DerivedQuantity,       // magnitude, x, y, z, von Mises, principal 1..3, ...
    pub spec: VisualizationSpec,
}

pub enum VisualizationSpec {
    Color { map: Colormap, range: Range, bands: Option<u8>, isolines: Option<u8> },
    Vectors { density_px: f32, scale: VectorScale },
    Streamlines { seeds: SeedRake, max_length: Length, tolerance: f32 },
    Isosurfaces { values: Vec<f64>, opacity: f32 },
    Deformation { exaggeration: Exaggeration, show_undeformed: bool },
    Volume { map: Colormap, opacity_ramp: Ramp },
    Chart { kind: ChartKind },           // line probe, waveform, Bode, Smith, eye
}
```

**Decision D-UIX-13:** Field colors come from Flux's per-pixel WGSL evaluators on the UI device, in phase 1 for H¹ Lagrange elements up to p = 4 on the immersed octree. *Why:* linear interpolation of high-order solutions misplaces peaks, and the UI's device avoids a host round trip (R6-16, R12-33). *Rejected:* fixed per-vertex sampling everywhere (silent error near stress concentrations); a separate post-processor. (revised in round 3)

Other discretizations, until FLX ships their evaluators, and tiers without compute use refined vertex samples, with interpolation error under 1% of the color range (target). Probes always use Flux's exact sampler, and display data never feed checks (D-FLX-22). During a geometric drag, physics results show as `Proxy`; from phase 3 Flux's reduced models answer parametric drags (D-FLX-37).

Rainbow maps distort data and fail readers with color-vision deficiency (Crameri, Shephard and Heron). Crucible ships the Scientific colour maps (v8.0.1): batlow for sequential data, vik for diverging data and a cyclic map for phase. Paul Tol's palette serves categories, and a value-suppressing palette (Correll, Moritz and Heer) shows uncertainty.

**Decision D-UIX-14:** Rainbow and jet colormaps are not offered, not even as an option; imported legacy presets map to batlow with a one-time notice. *Why:* evidence of distortion and accessibility harm, and defaults decide most users' choices. *Rejected:* offering jet "for familiarity" (familiarity is why the harm persists).

- **Legends** show the Field, quantity, unit, range, map, `ResultStatus` and fidelity. Values outside a fixed range draw hatched in out-of-range colors, and the legend counts the clipped area.
- **Extremes** carry automatic markers with value and location.
- **Validity and singularities.** `Extrapolated`, `Invalid` and `Unassessed` zones from COV's `ValidityEnvelope` are hatched and listed with their assumption. Inspection shows bound, basis and escalation options (COV). Flux's singular sets carry a glyph, and a check's region is outlined, so readers see what the check excludes.
- **Error overlay.** A toggle shows Flux's error-estimate Field, and the uncertainty palette combines value and error.

## Direct manipulation and code

Direct manipulation edits the same Ingot program the code panel shows. Sketch-n-Sketch showed that output edits can map back to small program changes, and Crucible applies the idea through provenance and Ingot's derivatives.

### From gesture to Ingot edit

Every manipulation produces an `EditPlan`: the intent plus ranked candidate edits that would realize it.

```rust
pub enum ManipulationIntent {
    MoveEntity    { target: Query, delta: Transform },
    SetMeasure    { target: Query, measure: Measure, to: Quantity<Dyn> },
    PlaceInstance { instance: InstancePath, to: Transform },
    CreateFeature { call: FeatureCall },
}

pub enum EditCandidate {
    SetLiteral    { site: LiteralSite, to: Value },                    // change one literal
    SolveLiteral  { site: LiteralSite, through: CallSite, to: Value }, // invert an expression
    SetParameter  { symbol: Symbol, to: Value, uses: u32 },            // a shared parameter
    InsertFeature { after: CallSite, source: IngotSnippet },           // a direct-edit feature
    SetPlacement  { instance: InstancePath, to: Transform },
}

pub struct EditPlan { pub intent: ManipulationIntent, pub candidates: Vec<EditCandidate>, pub chosen: usize }
```

1. **Driving literal first.** The first candidate is the literal whose call and role created the dragged entity, such as an end cap's extrude distance. Other literals follow by IIR dependence distance, and from phase 2 derivatives through `anvil::shape_velocity` refine the order.
2. **Solve through expressions.** For `width / 2`, ING's forward-mode derivatives solve for the free literal from phase 1. When several literals contribute, the plan lists each and never edits more than one silently.
3. **Warn on shared parameters.** "Used by 3 features" appears, and "change only here" introduces a new literal that the diff shows.
4. **Fall back to a direct-edit feature** over Anvil operations, with no privileged path.

During a drag, a chip states the candidate before release ("thickness 4 → 6.2 mm" or "adds `offset_faces` after `fillet`"). Tab cycles candidates, and the code panel shows a ghost diff.

**Decision D-UIX-15:** Gestures edit source through ranked edit plans, changing the driving literal or else appending a direct-edit feature, and a drag evaluates literal overrides so release writes one Change. *Why:* one model with three editors; intent survives where parameters exist, and history-free editing stays possible where they do not, as in Plasticity and Shapr3D. *Rejected:* edits that rewrite history invisibly; refusing direct edits on unparameterized geometry; derivative ranking in phase 1, which needs `shape_velocity` (R2-44). (revised in round 2)

A drag runs as AGT's `edit.stream`: a session-scoped stream of override updates that ends in one `edit.apply`. When a value fails to build, the handle shows the typed failure and the last value that built. Release then offers "Use 7.8 mm (last value that built)", "Keep 9 mm (fails to build)" or "Cancel".

Escape writes nothing. Overrides key by `LiteralSite`, which follows `#[was]`, so a concurrent rename maps the override to its new site and the drag continues (ING, R9-50). Only a deleted literal ends the drag, with a notice.

### Handles, push-pull and sketching

Features declare handles (linear, angular, radial, point, planar, count) in their metadata, so std and user packages behave alike. The gizmo draws arrows, rings and plane squares at a constant 96 px. Typing during a drag enters an exact value, or after `=` an expression.

Drags step by zoom-adaptive 1, 2, 5 increments. Alt (Option) moves freely, Shift locks the direction or inference, and Ctrl or Cmd gives one-tenth speed. Control-vertex drags on surfaces use Anvil's `Preview` re-evaluation with zebra and curvature Fields within 16 ms (target).

- **Push-pull** on an end cap changes the extrude distance. On other faces, phase 1 plans `anvil::offset_faces`, which rebuilds adjacent blends with the same parameters and ids; `move_faces` joins in phase 2. A blend that cannot regrow fails with `BlendRegrowFailed`, offering "remove blend" and "reduce radius".
- **Boolean choice.** A chip cycles New Body, Join, Cut and Intersect, defaulting to Cut when the drag enters material.
- **Sketches** start on a plane, datum or planar face referenced by `Query`, with the usual drawing and editing tools and construction geometry.

Anvil's `solve_constraints` runs every frame while under-constrained geometry moves, within MEC's solve targets, and release writes the solved seeds as one Change. The status bar states the remaining degrees of freedom, and MEC's `SolveReport` draws free motions as arrows.

Under-, fully and over-constrained geometry differ in color and stroke, and each conflict member offers its `Fix` (delete, reference or replace). "Constrain fully" asks an agent for an `EditPlan` preview.

Inference follows SketchUp: endpoints, midpoints, centers and intersections become `coincident`, and on-edge points `on(entity)`. Directions, equal lengths and 15° steps become the matching constraint, `equal` or dimension, and in 3D the same inferences become `Query` references. Candidates lie within 8 px for mouse and 16 px for touch, with 3 px hysteresis, and each accepted one becomes an explicit constraint call.

Selecting a feature shows its driving dimensions at a constant 12 px. Clicking one opens an inline editor for values, units, expressions and tolerances (`4mm ± 0.1mm`), bound through the same `EditPlan`.

In assemblies (phase 2), mates draw as glyphs and Instances drag within their degrees of freedom through MEC's solver. "Test motion" moves a mechanism without writing and highlights interference.

Undo writes inverse Changes for the principal's own Changes, and redo writes them again; others' work is undone by rejecting or reverting its Proposal. A drag, dialog or command is one step, and typing groups by word or a 500 ms pause. A later edit to the same statement offers keep, revert or diff.

## Review, agents and collaboration

A Proposal opens in the Review preset on its saved views, with its CI evidence first.

| --- | --- |

| Rationale | Text from outside the reader's delegation chain, as `ExternalText` with its origin |

KLN defines the `ReviewVerdict` and `Comment` records and required-review policies; UIX owns `CommentAnchor` and the display (R9-29). Recording which tabs a reviewer opened is an organization setting (D-UIX-30).

- **Feature diff.** Feature lists aligned by `CallSite`, marked added, removed, modified (old → new), reordered and suppressed.
- **Geometry overlay.** Base-only faces ghost in `diff.base` and target-only faces fill in `diff.target`, with a deviation map on modified faces. Side-by-side and swipe views also exist.
- **Correspondence.** Same `EntityId` means same face, and `HistoryRecord` links pair splits and merges; without provenance, a labelled distance diff applies. Symmetric-difference regions are shown and do not block (contract 7.1).
- **Metrics and source.** Each metric shows base, target, delta and bound, reading "within error" inside combined bounds. Source diffs are structural, with moves as moves and hidden characters marked.

**Decision D-UIX-17:** Every comparison uses a blue (base) and orange (target) pair with a second cue: ghost versus solid fill, + and − gutter marks, and labels. *Why:* WCAG 1.4.1 (color is never the only means), and red and green collide for many readers with color-vision deficiency. *Rejected:* green and red for added and removed; color alone.

Merges never endorse free text (contract 7.6). "Endorse text" shows each untrusted span verbatim, with invisible and bidirectional characters highlighted, and endorses one span per action.

```rust
pub struct CommentAnchor {
```

### Approvals

Release and change-order Approvals sign the `ApprovalSubject` (contract 5), so re-review after a subject change shows only the delta. Release is an Act, approved on the approval page.

**Decision D-UIX-29:** Act approvals happen only on the server-generated approval page, served from its own origin and relying-party id, and opened outside the client's own code on every platform. *Why:* script injected into the main origin must never reach a passkey ceremony (R11-05), and Apple apps cannot use passkeys for unassociated self-hosted domains (R12-15). *Rejected:* a secure dialog per OS; approving inside the app's process, an in-app webview or an MCP host's viewer. (revised in round 3)

- **Isolation.** The page lives at `approve.<deployment>` and renders only server-generated text under a strict content security policy (`default-src 'none'`, scripts by hash, no framing). Challenges go only to that origin, with `SameSite=Strict` cookies and no CORS. Each challenge is the hash of plan digest, request id and approver id.
- **Clients.** The web client opens it as a top-level page. Native clients use `ASWebAuthenticationSession` on macOS and iPadOS and the default browser on Windows and Linux (PLT). The session is bound to the request id, returns through a `crucible://` callback, and lets the browser run WebAuthn for any relying party.
- **Content.** The page shows what contract 7.6 lists, including a physical-effect plan's section, plus the context's integrity flags (AGT). Steps at the device read as numbered instructions to the person there (R10-17).
- **Delivery and limits** follow contract 7.6: Cedar-assigned approvers' inboxes only, "not assigned to you" for anyone else, pending limits and denial lockouts.
- **Credentials.** Only a device-bound credential enrolled for approval approves (contract 7.6). Enrolment starts from a signed-in Crucible desktop or tablet app, which reports its form factor, or uses an allowlisted security key. The server refuses credentials that WebAuthn Level 3 flags as backup eligible, its multi-device credentials, so synced passkeys sign in but never approve.

Phone clients list approval requests read-only and offer no approval (contract 9).

**Physical effects.** The Manufacture preset offers the transfer Acts (`send_to_machine`, `send_robot_program`, `store_machine_job`, `send_print_job`) and, for material-extrusion printers covered by a site policy, `start_print`; Electronics offers `flash_device`. The `start_print` confirmation takes the one-time code from the printer's display, or waits for the printer-side button, within 10 minutes before the start. The UI never offers cycle start, resume or jog for any device it transfers to.

**Exports.** A person's export of an uncontrolled `public` or `internal` payload to a local folder or application is an audited local write (contract 7.6). Any other export opens an export Act's plan. A desktop install without a team server works and exports locally, and its Proposal, release and Act commands read "needs a team server" (contract 13.2).

### Agents

The command palette (Ctrl+K or Cmd+K) ranks commands, features, entities, files, branches, Proposals and settings by match, recent use and preset. Palette, menus, toolbars, keymaps and context menus derive from one command registry. A query that matches nothing, or starts with `>`, goes to the default agent, and the palette says so first.

The agent panel shows the request, a scope chip (permissions, cost cap, time limit), the plan as `api` calls, a timeline and a budget meter. Its controls are Pause, Steer, Fork and Take over. Attachments (selection as `Query`, views, comments, files, sketches) enter the agent's context as `ExternalText` with their origin, never as goal text.

**Decision D-UIX-18:** Agent activity shows as `api` calls and Changes on the agent's own branch, and any agent action can be inspected, replayed or reverted like a person's. *Why:* trust comes from seeing real actions, not narrated summaries, and the contract confines agents to branches. *Rejected:* chat-only output (no evidence); agents editing the user's working branch (unreviewable).

- **Who steers.** Only the delegating human steers, pauses, forks or takes over. Anyone else's steer or @mention becomes an inbox request for that human (R5-43).
- **Steer, pause, rewind.** Steer and Pause use AGT's `session.control` (phase 2, with the hosted crew), and a steer arrives at the next step boundary. Pause stops after the current `api` call, and Kiln cancels in-flight Evaluations, so no half-applied edit exists. "Continue from here" forks a branch at a timeline Change.
- **Pins and questions.** Pins ("do not change mounting holes") become `require` checks on the branch. Agents ask through typed question cards whose answers return as typed data.
- **Verdicts.** Reject needs a reason, given to the agent. Cherry-picked features form a new Proposal, which runs checks before approval.

Variant sets (phase 2) show up to 16 linked viewports with one camera, beside a sortable table, a Pareto scatter plot and parallel coordinates. "Promote" turns a variant into a Proposal.

## Simulation, manufacturing, drawings and electronics

### Studies and results

A study is Ingot source with Flux's semantics, built by selection: a template, then faces or Bodies with a condition (fixed, force, pressure, preload, temperature, convection). Each becomes a statement with a `Query` and typed quantities, such as `pressure(web.face(role: end_cap), 2.5MPa)`, drawn as scaled glyphs. Flux's pre-flight flags unassigned Materials, unconfirmed contacts, rigid-body modes, unit errors and envelope warnings, each with a fix.

`Interactive` studies re-run after edits within contract 13.3's row, and `SignOff` Evaluations queue locally or on workers with position, time and cost. The results panel lists each check's verdict, value, limit, margin and bound. For the canonical bracket it reads "`stress < 0.6 × yield` beyond 8 mm from the clamp: `Pass`, margin 18% (`Estimated`, ±4%)".

A region that meets a singular set gives `Undecided { SingularPoint }` with the fix "exclude a stated distance". A bound wider than the margin offers refinement or `SignOff`, and two Evaluations compare as a difference Field.

### Manufacturing

Contract 13.2 puts CAM, posts, stock simulation and slicing in phase 2. Phase 1's Manufacture preset therefore shows MFG's DfAM check Fields, the 3MF build layout and the cost panel.

- **Cost panel (phase 1).** Unit cost at chosen quantities by Part, process and source, each line with assumptions and range. Edits show deltas with their cause ("fillet radius 2 → 3 mm: machining −$0.42"), and quantity curves show process crossovers. Quotes replace estimates with their date, and cost targets are checks.
- **Toolpath playback (phase 2).** Polylines are dashed by move type and colored by type or feed. Tool, holder, machine and stock come from MFG, with stock labelled "display" between key frames. Collisions are marked where and when they occur, and the timeline scrubs by time or workingstep.
- **NC code panel (phase 2).** Posted NC text links both ways through MFG's `BlockMap` to toolpath points, workingsteps and design features (R4-06). Each finishing workingstep shows its cutter compensation mode and declared wear range, and G41 and G42 blocks show their D register (MFG, R10-13).
- **Setup sheet and additive (phase 2).** MFG's `setup_sheet` previews and diffs like any drawing, and a layer slider shows per-layer paths from Crucible's slicer.

The palette's CAM synonym set maps "operation" and vendor terms to workingstep commands (R4-37).

### Drawings

MEC owns drawing standards, `auto_drawing` and `revision_markers`; UIX owns the editors. PMI shows on annotation planes, filtered by saved view. A drawing is an Ingot file of sheets, views and annotations, where each view is a `ViewState` and each dimension references entities by `Query`.

- **Sheet editor.** A 2D canvas shows Anvil's exact hidden-line views; placing views and dimensions writes Ingot edits.
- **Driving dimensions.** Editing a driving dimension on a sheet writes model source through the same `EditPlan` as a drag (D-UIX-15). A dimension that traces to exactly one literal writes it, and otherwise the editor offers ranked plans. Driven and reference dimensions stay read-only (MEC, R8-45).
- **Automatic drawings.** The editor calls MEC's `auto_drawing` and shows the result as an `EditPlan` preview; agents refine it afterwards in a separate Proposal (R4-38).
- **Revision markers.** The editor previews MEC's markers and revision rows before the release plan is prepared.
- **Dangling references** show in the danger style with their `ResolveError` and fixes, never re-attached silently.

### Electronics

**Decision D-UIX-27:** Schematic and layout editors draw through the public `crucible:ui/canvas2d` world: retained 2D primitive buffers with layer, net and entity ids, drawn and hit-tested by the renderer. Per-move tools such as ELX's router run in the engine process on an interactive edit lane and stream geometry each frame through `api`. *Why:* element trees cannot draw a layered board with a live router head within 2 ms, and principle 1 needs an open mechanism (R4-04). *Rejected:* electronics as element-tree panels (too slow); a privileged built-in board view; package shaders.

Buffers hold lines, arcs, polygons and text, and placement drag runs live rule checks the same way. The edit lane is the drag path above: `edit.stream` updates on PLT's `Interactive` pool lane (R9-07). The schematic, layout and constraint-manager canvases show ELX's contents within ELX's targets, such as 16 ms per mouse move with 50 shoved items.

The renderer offers net highlight, high-contrast and dimmed-layer modes over any buffer. A schematic label is connectivity, so editing it renames the net in source. A drawn group spanning two nets draws in the danger style (ELX's `schematic_matches_network`).

Selection is one set of `EntityId`s, so schematic, layout, 3D board and enclosure cross-probe with no extra work.

## Input, accessibility and localization

### Pointer, keyboard and keymaps

Zoom goes toward the cursor, and orbit pivots on the surface point under it. Trackpads pan with two fingers, pinch to zoom and orbit with Shift. A view cube offers named views, F fits the selection and Shift+F fits all; double click selects the feature that made an entity.

A keymap is a TOML file layered over a preset:

```toml
preset = "fusion"

[[binding]]
keys = "Ctrl+Shift+E"
command = "feature.insert"
args = { feature = "std::mech::extrude" }
when = "preset == design && !text_focus"
```

### Devices

**Decision D-UIX-31:** Crucible reads 3D mice as HID devices through PLT's `DeviceIo` on every desktop OS and through WebHID in Chromium; vendor drivers are optional. *Why:* no vendor SDK licence sits on a critical path, and one decoder serves every platform (R12-33). *Rejected:* the vendor SDK as the only path (its licence becomes a dependency); `spacenavd`, a GPL-3.0 daemon, as the Linux path.

Retained counsel checks each vendor's device terms before its devices are listed. Other browsers offer the desktop app.

- **Pen and touch.** Pressure and tilt reach sketch tools, and pen hover shows inference. Touch layouts give 44 px targets, a 12 px pick radius, a 140 px gizmo and a radial tool menu. Every drag has a tap-then-type path (WCAG 2.5.7).
- **XR review (phase 3).** Multiview stereo at 90 Hz per eye on G1, true and tabletop scale, ray selection, hand-placed sections, comments and verdicts. Shared sessions follow in phase 4 and passthrough overlay in phase 5.

**Decision D-UIX-33:** XR review runs on OpenXR runtimes natively and on WebXR in browsers, which reaches visionOS: Safari 18.0 for visionOS 2 "adds support for `immersive-vr` sessions with WebXR". *Why:* the web build covers Apple's headset without another native shell (R12-33). *Rejected:* a native visionOS shell before the founder approves it as a Tier 2 target (contract 13.2); no visionOS path.

## Performance, privacy and extension

Contract 13.3 owns the shared performance rows, and PLT owns browser startup and memory. UIX adds its own targets: 8.3 ms interface-only frames, palette results in 30 ms over 100,000 items, and 8 ms keystroke-to-paint on 50,000 lines. Arrived results display within 50 ms, and no UI-thread stall exceeds 50 ms.

**Decision D-UIX-28:** Above `internal`, nothing the UI sends outside the organization carries content, and copies stay out of clipboard history and cloud clipboards where the OS allows. *Why:* labels stop at `api` unless egress channels consult them, and ITAR's end-to-end condition fails once a third party holds plaintext (R5-16). *Rejected:* content-rich notifications for every label; per-feature opt-outs instead of one auditable rule.

Notifications, emails and push payloads carry ids and generic text, never snapshots or names. Crash reports upload only signature and module list, bundles go only to the organization's own server, and a policy can forbid copying. PLT keeps the CAS, journal and caches out of cloud-synced folders and OS backup.

**Decision D-UIX-22:** UIX's telemetry uses PLT's one opt-in pipeline and schema (D-PLT-39) from phase 2, and the signed policy `telemetry.performance = off` with an egress allowlist turns it off. *Why:* engineering data is confidential, and two pipelines with different payloads and retention cannot both be honest (R5-29, R9-32). *Rejected:* opt-out telemetry; a separate UI pipeline; compile-time exclusion, which contradicts PLT's single binary. (revised in round 3)

UIX contributes frame-time histograms per tier, interaction latencies, command counts, typed failure codes and settings. It never sends source, geometry, names, paths, values or prompts, and an inspector shows each payload first.

Minidumps can hold design data in thread stacks, so uploads and reproduction bundles ask first and show their content. After a crash the workspace restores the last `ViewState`, panels and comment drafts, and every finished gesture is already a Change.

Test suites cover rendering correctness, visual regression, interaction, accessibility, performance and usability, each with an oracle below. Input to photon runs on PLT's camera rig at each gate.

**Decision D-UIX-32:** UIX meets its target at each gate with 90% success on the phase's core tasks, measured by an outside usability lab. *Why:* task success shows whether professionals can do the work, while scores from people with strong habits in other tools measure familiarity (R12-33). *Rejected:* a System Usability Scale of 75 as a criterion (it penalizes unfamiliarity); no usability target (oracles cannot show that work is learnable).

Core tasks are the steps of the phase's golden products, and System Usability Scale scores are only tracked.

### Extending the interface

Principle 1 applies to the interface: domain views from other tabs use the extension points open to any package. Dialogs and handles come from `Feature` metadata, commands are registry entries, visualizations are `VisualizationSpec`s, and themes, keymaps, templates and tutorials are data. Code-driven views are Wasm components:

```wit
package crucible:ui@0.1.0;

interface view {
    use types.{element, ui-event, command-call};
    render: func() -> element;                              // element tree from data read through api
    handle: func(event: ui-event) -> list<command-call>;    // calls go through the registry and api
}

interface canvas-host {
    use types.{primitive-batch, layer-id};
    submit: func(layer: layer-id, batch: primitive-batch);  // imported; retained until replaced
}

interface canvas {
    use types.{hit, command-call};
    on-hit: func(hit: hit) -> list<command-call>;           // hits resolved from the same buffers
}

world panel    { import crucible:api/read; import crucible:api/edit; export view; }
world canvas2d { import crucible:api/read; import crucible:api/edit; import canvas-host; export view; export canvas; }
```

- **Sandbox.** Panel and canvas Wasm components get no files, network or clock and reach data only through `api`. `crucible:api/edit` needs the user's grant per package. Third-party ones run in PLT's sandboxed worker process (contract 7.4).
- **Budget.** Panel UI logic gets 2 ms of CPU per frame, and three over-budget frames pause it with a notice.
- **Chrome.** Every panel shows its package identity and may not use modal or system-styled elements, so it cannot imitate Crucible's dialogs. Panel edits record the package in `ChangeProvenance` (R5-42).
- **Host services.** The toolkit supplies accessibility, theming, localization and keyboard access, and selection is one shared set of `EntityId`s.

**Decision D-UIX-23:** Built-in and package views extend the interface only through declarative data, Wasm component panels and Wasm component canvases, never through shaders or the GPU. *Why:* no privileged code, plus accessibility, theming, localization and parity for every panel, with canvases for dense 2D editors (D-UIX-27). *Rejected:* native shared libraries (unsafe, per-OS, impossible on the web); webview panels (second runtime); custom shaders (portability and review cost). (revised in round 2)

- **Windows 11.** DX12 by default, Vulkan as an alternative; G1 needs Shader Model 6.6. On Windows ARM64, Chrome keeps WebGPU behind a flag, so browser users run G3.
- **macOS.** Apple's feature tables give 64-bit atomic min and max to Apple8 GPUs (M2-series) on macOS and to every Apple9 GPU. M1-series Macs (Apple7) therefore run G1 without `compute_raster`. Indirect-count draws exist only on DX12 and Vulkan, so every tier uses single indirect draws. Display P3 is the default, and ProMotion gets 120 Hz interface frames.
- **Linux.** Vulkan; Wayland and X11 with fractional scaling; AT-SPI. IME runs through winit on both, and X11 reports a caret position rather than an area.
- **Browsers.** WebGPU is on by default in Chrome and Edge on Windows, macOS and ChromeOS (since 113) and in Safari 26. Firefox has it on Windows (since 141) and Apple silicon (since 147, or 145 on macOS 26). On Linux, Chrome enables it only for Intel Gen12+ and NVIDIA on Wayland, so many Linux users run G3. G2 page pools split into 128 MiB bindings.
- **Browser services.** The CAS and replica live in OPFS, and a service worker caches the shell. Shared-memory threads need a secure context and cross-origin isolation, so the app's pages are served cross-origin isolated. EditContext and WebHID are not Baseline and have fallbacks, and Noto CJK downloads on first use.
- **Tablets (phase 3, PLT).** On iPadOS the web build runs in a thin WKWebView shell with WebKit's WebGPU (contract 7.4). It runs only first-party Wasm components, evaluates registry ones remotely, and shows packages only as dependencies of an opened design. Android Chrome has WebGPU from Android 12, and device-loss recovery is tested on Tier 2 hardware every release.
- **Everywhere.** Engineering styles stay SDR, so colors match across displays. Tier 3 builds use Vulkan and AT-SPI without a support commitment. Only the shortcut modifier, text chords, menu bar location and native dialogs differ by OS, listed in one conventions table owned with PLT.

## Contract change requests

- CCR-UIX-5, one device rule for Act approvals: accepted in contract v5, section 7.6.
- CCR-UIX-6, `RenderProfile` beside `ViewState`: accepted in contract v5, sections 5 and 2 (Snapshot).
- **CCR-UIX-7, name-free `DisplayPackage` (contract 5).** Contract 5 should describe a per-Body clustered tessellation keyed by `GeometryId`, with stated chordal error and canonical-entity-number back-references that consumers join to `EntityId`s through the Body's name table. *Reason:* a name-free key cannot carry names, and equal geometry in two designs must pick each design's own entities (R8-18).
- **CCR-UIX-8, `compute_raster` capacity (contract 13.3).** The G1 scene-capacity figure applies to adapters reporting `compute_raster`, and others, such as M1-series Macs, declare a measured capacity. *Reason:* some Tier 1 GPUs lack the 64-bit atomics it needs (R12-28).
