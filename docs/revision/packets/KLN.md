### R2-02 · Critical · Targets: ANV, ING, KLN, MEC, CONTRACT
**Section:** ANV Symbolic perturbation; Memory layout; Determinism rules; ING Entities and call sites; MEC Solver method, Patterns and mirror (`by_density`), D-MEC-22; KLN CRDT over the syntax tree; Storage format
**Problem:** EntityIds hash OpSites whose statement identity is a Loro node id, which is not a function of the source text and is dropped by `crucible export git`. Anvil and MEC nevertheless use EntityIds to order, tie-break and seed geometric computation, so meshes, `by_density` placements, reduction orders, solver decompositions and variation statistics depend on invisible metadata. Identical text can give different bits, a reviewer cannot predict geometry from a diff, and a design exported to Git and re-imported may not rebuild identically, which breaks D-MEC-5 ("the result must not depend on edit history, only on source") and the exit guarantee.
**Evidence:** ANV: SoS "perturbation order is the canonical vertex order of the encoded Body (face-group EntityId, then local index)"; row order "Morton code ... then EntityId"; BVH "EntityId tie-breaks"; independent sets "priority is a hash of the element's deterministic id". MEC: `by_density` "seeded from EntityIds"; decomposition "Ties break by EntityId"; Sobol "scramble seed derived from the design's EntityIds"; witness values "pseudo-random rationals derived from EntityIds". ING: statement identity is "The BlockId of the enclosing statement block"; external edits "match blocks by GumTree, so most BlockIds survive". KLN: "Block identities are Loro tree node ids"; "crucible export git writes Ingot text and lockfiles".
**Fix:** Add a label-invariance rule to contract 7.3: an operation's geometry, connectivity, Field values and statistics are invariant under any injective renaming of input EntityIds and OpSites; only label sections may change. Implement it with canonical orders from geometry and topology (box minimum, box maximum, entity type, defining parameters; distinct entities of a valid Body never tie on all of them), SoS indices and independent-set priorities from that order or from geometric content hashes, and seeds for `by_density`, Sobol scrambles and witness values from hashes of argument values and input geometry. Add oracle ANV-O-LABEL-1: rebuild every golden product with all BlockIds re-randomized and require identical geometry hashes (label sections excluded) and identical check values.

### R3-01 · Critical · Targets: CONTRACT, ANV, KLN, FLX
**Section:** CONTRACT 7.2 (two-stage caching); ANV "EntityId", "Persistence and versioning"; KLN "Keys and behavior versions", "Revisions and lifecycle states" (D-KLN-26); FLX "Fields and errors (`flux-field`)"
**Problem:** Every identity that caching, early cutoff, revisions and approvals use hashes entity names, and names hash upstream `OpSite`s transitively through "generating entity ids". The "site-free geometric stage" is keyed by its inputs' `ObjectId`s, which contain those names. So it can be shared across designs only for an operation whose inputs carry no names, and a refactor that changes no geometry (the language service's "extract feature" or "inline binding", which change feature instance paths) changes every downstream Body and Field `ObjectId`. Contract 7.2's cross-design sharing, D-KLN-26's promise and early cutoff after refactors therefore cannot hold as specified.
**Evidence:** ANV: the Body encoding's sections hold "`EntityId`s, tolerances, attributes, lineage summary"; rows are ordered by Morton code "then `EntityId`", and "a row ends a leaf when a hash of its EntityId has its low 8 bits zero". EntityId `inputs` are "The EntityIds of the generating entities". KLN keys every Op by "Ordered `ObjectId`s of every input value". FLX: `pub domain: DomainRef, // Body content hash plus EntityIds`. D-KLN-26: an edit that leaves the definition unchanged ("a refactor, a comment, a change elsewhere in the repository") "never invalidates a release".
**Fix:** Give every Body two identities in `base`. `GeometryId` hashes the canonical encoding with names, lineage and name-keyed attributes removed, rows ordered by spatial key only and entities numbered in that order; `ObjectId` hashes the full named encoding. Amend 7.2: "The geometric stage of an entity-naming Op is keyed by its inputs' `GeometryId`s. It numbers new entities canonically and refers to input entities by canonical number. The relabeling stage is keyed by the geometric output's id, the `OpSite` and the inputs' name maps, and it assigns `EntityId`s." Flux results key on `GeometryId` plus the canonical numbers of the entities their conditions reference. D-KLN-26's `ItemDefinition` and approval digests use `GeometryId` plus PMI attached by canonical entity number. New ANV oracle: two designs that build the same geometry at different sites share every geometric-stage entry along a 20-operation chain.

### R3-02 · Critical · Targets: CONTRACT, KLN, AGT
**Section:** CONTRACT 5 (`Labels`); KLN "Memoization, verification and backdating", "Distributed and remote evaluation", "CRDT over the syntax tree", "Export control", Rust API (`Label`, `DataClass`)
**Problem:** Kiln is said to "join" labels, but three mechanisms lose or leak them. Backdating keeps `changed_at` when bytes are unchanged, so an input relabelled from confidential to ITAR with identical bytes never reaches its dependents. `DataClass` is one string, so the join of two incomparable classes (two export regimes, two customer scopes) cannot be represented. And a live document is one Loro replica per package, so a participant who "does not satisfy a label" still receives every CRDT operation of the labelled blocks.
**Evidence:** Contract 5: "`DataClass` (public, internal, confidential, export-controlled with regime and classification) ... Joined through every derivation by Kiln". KLN: "If the new value equals the old one, keep `changed_at` (backdating)"; `pub struct DataClass(SmolStr)`; "Organizations add classes such as `cui` or `customer:<name>`"; D-KLN-22 "one document per package"; "a participant who does not satisfy a label sees neither the labelled content nor its geometry". A replica must hold every causally prior operation to converge, so a relay cannot filter operations per recipient inside one document.
**Fix:** (1) Contract 5: `Labels` is a product lattice: `level` (public < internal < confidential), `controls: Set<(Regime, Classification)>`, `scopes: Set<Scope>`, `integrity`, `licences: Set<DataLicence>`. The join takes the maximum level and the union of each set, and a principal may read only if it satisfies every element. (2) KLN: a node's label is a separate memo output with its own `changed_at`. Verification re-joins labels from current inputs even when the value backdates, and a shared-cache hit returns only the value, with the label recomputed locally. (3) An encryption domain is keyed by tenant and canonical label set. (4) The unit of live replication is (package, label set). Blocks labelled above a document's label live in a separate document that only cleared participants receive, and the relay refuses moves into a lower-labelled document. (5) Extend `repo/labels`: relabelling an input with unchanged bytes updates every dependent label with zero re-execution, and an uncleared participant receives zero operations of a labelled document.

### R3-03 · Critical · Targets: ING, KLN
**Section:** ING "Strict, ordered, and failure-aware" (D-ING-11), "Resource limits"; KLN "Errors as values" (D-KLN-6)
**Problem:** `try` and wildcard `err(e)` arms catch any `Failure`, and nothing excludes environmental failures (out of memory, device loss, cancellation, a budget exhausted mid-run). Nor does anything exclude a `DependencyFailed` whose upstream was environmental. A feature can therefore take its fallback branch because a worker ran out of memory, and Kiln caches the fallback geometry as a deterministic value. This breaks principle 4 and can poison the shared cache.
**Evidence:** ING: "`Failure` is an extensible union ... a match over `Failure` needs a wildcard arm"; "`try e` turns propagation into a value of type `Result<T, Failure>`"; "When the host cannot supply memory ... evaluation fails with an environmental `ResourceExhausted`, which Kiln never caches". KLN: "A node that needs a failed value fails with `DependencyFailed { upstream }`"; "Exhausting a budget mid-run is an environmental failure and is never cached".
**Fix:** Contract 7.2 and ING define two disjoint classes. A deterministic `Failure` is catchable and cached. An environmental `Abort` covers cancellation, `ResourceExhausted`, device loss, budget exhaustion, worker loss, an unavailable retired version and the limits of R3-04. `Abort` is not a `Failure`: `try` cannot observe it, it propagates to every transitive dependent, and no node that observed one writes a memo entry, CAS object or attestation. `DependencyFailed` wraps only deterministic failures. New oracle `kiln/abort`: inject environmental faults at random Ops in 10,000 runs; every value that reaches the memo or shared cache equals the fault-free run's value.

### R3-04 · Critical · Targets: ING, KLN
**Section:** ING "Resource limits", "Strict, ordered, and failure-aware"; KLN "Scheduling and parallelism"
**Problem:** Ingot's claim that every evaluation ends in a value or a typed failure is false. Every limit applies per feature call, and each feature call is a separate Kiln node with fresh limits. A feature that calls itself with a new argument (`f(n) = f(n + 1)`) therefore builds an unbounded chain of nodes, and Kiln detects only a node that reappears on its own stack. Total work is also unbounded: 10⁹ steps per call times any fan-out times depth.
**Evidence:** ING: "Limits apply per feature call ... Feature calls and `#[memo]` function calls are Kiln nodes with their own limits ... Termination still holds, because every call is bounded and call depth is bounded"; the 2,048-frame depth limit is a "Default per feature call". KLN: "When a node demands a node already on its own active stack, Kiln returns `EvalError::Cycle`".
**Fix:** Kiln enforces two evaluation-wide limits as environmental `Abort`s (R3-03), so they never change a cached value. One is a demand-depth limit on nested node demands (default 10,000); the other is an aggregate fuel governor per Evaluation, taken from the request's budget. Restate ING's guarantee: "every node terminates with a value or a typed failure; every Evaluation terminates or aborts". New oracle ING-O-24: `f(n) = f(n + 1)` aborts with `DemandDepthExhausted` on every Tier 1 target and leaves no memo entry.

### R4-01 · Critical · Targets: CONTRACT, MFG, AGT, KLN

**Problem:** No tab separates moving data to a device from starting motion, heat or energy, and none forbids Crucible from starting a machine remotely. The OPC UA adapter's capability set excludes `Start`, `StoreAndStart`, `Resume` and `RevokeStart`. KLN: `unattended_safe` is a signed site policy, never self-declared by a runner and never granted to machine tools, robots or lasers; agent-branch runs still need an Approval of the program digest. MFG robot offline programming: posted robot programs are proved first in the robot's manual reduced-speed mode and never alter the controller's safety configuration (safety-rated zones, speed limits); the robot safety data package cites the 2025 editions above. ### R4-03 · Critical · Targets: ELX, KLN
**Section:** ELX Writing a circuit; State of the art (connectivity capture); KLN Merge (D-KLN-21).
**Problem:** Because `connect` accumulates idempotently as a set union, two branches that each attach the same pin to a different net merge without textual conflict and silently short the two nets. None of KLN's five merge conditions catches it: the merged program compiles, Queries resolve, ERC passes unless pin types or voltage domains clash, and DRC follows the merged netlist, so the short becomes the design. ELX's merge target scores this case as a success.
**Evidence:** ELX: "`connect` statements accumulate into one value, and connecting the same pins twice is idempotent."; State of the art target "Scripted concurrent-edit branch pairs, target 100% merged without manual conflict when edits touch different nets". KLN D-KLN-21: merge succeeds when the design "compiles, resolves, passes every check that both parents passed, and shows no new geometric overlap or interference". Example: branch A adds `connect(u1.pin("PA5"), led_net)`, branch B adds `connect(u1.pin("PA5"), button_net)`; the merge joins both nets through PA5.
**Fix:** KLN adds a sixth merge condition: "Connectivity. The driver computes the net partition (pins per net) of base, both sides and merge. A merged net that unions nets that are distinct in the base and in each side is `Conflict::NetMerge`, naming the pins, both nets and both Changes. Net renames are matched by provenance, not by name." ELX adds an ERC rule that two named nets join only through an explicit `tie(...)` element (R4-22). Replace the ELX target with "100% of net-merging branch pairs reported as conflicts; 100% of non-overlapping pairs merged clean". Apply the condition to harness `Circuit`s and `std::systems` interface connections too.

### R5-01 · Critical · Targets: AGT, KLN, CONTRACT
**Section:** AGT Safety and security (Untrusted content is data; Taint and the Rule of Two; Data classes and model endpoints); KLN Security (Export control); contract §5 `Labels`, §7.6
**Problem:** Kiln joins labels through derivations, but an agent's model context is a derivation path the design never labels. A session that reads ITAR content in one repository can write it, unlabeled, into another, because no write-down rule exists. An external host that opens one session per repository mixes them without Crucible knowing. Untrusted typed values (numbers, enums, `SuggestedFix` edits returned by third-party packages) are declared non-tainting, so they can steer a "clean" session's edits and re-enter the design as trusted literals that qualify for auto-merge.
**Evidence:** AGT: "Typed numbers with units, enums, `EntityId`s and identifiers that Crucible generates cannot, so untrusted values of those kinds keep their label but do not taint a session that reads them." Contract §5: Labels are "Joined through every derivation by Kiln and enforced by `api` at every boundary". Contract §7.6 taints a session only when it reads "raw text". `SessionOpen` binds one repository, and nothing joins labels across the sessions of one host. AGT's own rule, "derived values take the most restrictive combination of their inputs", applies to the model's output as much as to a Kiln node, but the design never labels the context that produces it. 22 CFR 120.56 defines release of technical data to include inspection by, and oral or written exchanges with, foreign persons (https://www.ecfr.gov/current/title-22/chapter-I/subchapter-M/part-120/subpart-C/section-120.56), so an unlabeled copy that later reaches a supplier or a hosted model is a spill.
**Fix:** (1) Every model context carries a label: the join of the labels of every value returned to it, typed or textual. For the hosted crew the context is the conversation. For external hosts it is the OAuth token family (client instance plus user), shared by every session that family opens. (2) Split integrity into `instruction_tainted` (free text or images read) and `data_untrusted` (any untrusted value read). (3) Every write (edit, Proposal, comment, review, exploration record, Act payload) carries at least the context's confidentiality label and data-integrity flag. A write to a destination with a lower label fails with `label.write_down` unless a declassification record signed by two people, one of them an `export_officer`, names it (R5-15). (4) Return untrusted typed values by handle (`ValueRef`), and let edits cite the handle (`SetParameter { value: FromRef(h) }`) so the label follows exactly. Label `SuggestedFix`es from third-party code untrusted, and forbid them to add dependencies or touch Checks, tolerances, policy files or protected paths. (5) Auto-merge and class R1 require `data_untrusted == false` for every authoring context. (6) Extend O-AGT-8 and O-AGT-17: write-down and label-laundering attempts count as successful attacks, and tripwire strings from `export_controlled` repositories must never appear in a lower-labeled repository.

### R5-02 · Critical · Targets: AGT, KLN, ING, CONTRACT
**Section:** AGT Untrusted content is data (trusted origins; Endorsement), Independent verifier, Text descriptions (D-AGT-10)
**Problem:** Only import-derived strings are wrapped in `external(...)`; comments, doc comments, string literals, identifiers and description templates that an agent writes into Ingot are ordinary source. The verifier reads the Proposal's design untainted, so an author agent can address it in a comment. Once a human merges the Proposal, endorsement makes that text trusted on `main` permanently, where every later "clean" session and canonical `inspect.describe` output read it. D-AGT-18's guarantee that untrusted content "can never become instructions" is therefore false.
**Evidence:** AGT trusted origins include "Ingot source on protected branches". AGT: "When a human approves and merges a tainted Proposal, its content becomes trusted on the target branch. This covers geometry, parameters and source the human reviewed." The verifier "sees the requirements, the design, the semantic diff, the CI report and the rationale's structured fields". D-AGT-10 context: "a feature's doc metadata supplies its phrasing", and only "Templates from unverified publishers are untrusted text". The non-tainting exemption covers "identifiers that Crucible generates", not identifiers an agent writes.
**Fix:** (1) `repo` keeps span-level integrity provenance: each source span records the integrity of the context that wrote it, and merges preserve it. (2) `read.source`, `read.outline`, `read.docs` and `inspect.describe` return free-text spans as `ExternalText` handles when their author is outside the reader's delegation chain or their integrity is untrusted. Free-text spans are comments, doc comments, string literals, description templates, and identifiers not produced by the compiler or typed by a human. (3) Narrow endorsement: a human merge endorses structure and typed values, never free text. Free text becomes trusted only through an explicit per-span "endorse text" action that shows it verbatim, with invisible and bidirectional characters highlighted. (4) The verifier reasons over a typed view (IR, semantic diff, Check results) with the author's free text elided. (5) Add injection-suite cases: an instruction planted in a merged doc comment, identifier or description template must not change a later clean session's actions or the verifier's verdict.

### R5-03 · Critical · Targets: KLN, CONTRACT, AGT, FLX, ELX, COV
**Section:** KLN Distributed and remote evaluation (D-KLN-9), Threat model (Cache poisoning); contract §7.1 (Kiln)
**Problem:** The machines allowed to sign shared-cache attestations (CI runners and organization workers) also evaluate untrusted Proposals and run untrusted native code as External Ops (supplier FMUs, IBIS-AMI DLLs, emulators) inside ordinary Linux containers. One escape yields a signing identity that can map any `OpKey` to any output, and 1% spot re-execution catches a poisoned entry that a release consumes once with probability 0.01. Every tenant shares the global public cache domain, and no trust rule stops one tenant's builders from poisoning std results for all of them.
**Evidence:** D-KLN-9: "Only trusted builders write the shared result cache: CI runners and the organization's workers." KLN: "Kiln continuously re-executes 1% of shared cache hits"; residual risk "A compromised CI worker, caught statistically by spot re-execution". COV: "External tools run only in Linux containers on team servers or cloud workers (D-COV-12)". FLX: "FMUs from outside Crucible are untrusted native code." KLN: values with all-public inputs "live in one global public domain that every tenant shares".
**Fix:** (1) Split the worker pools. `untrusted-eval` workers run Proposal CI from agent and external branches and every External Op, in single-use microVMs (Firecracker- or gVisor-class). They hold no attestation key and write only to a per-Proposal namespace. `trusted` builders evaluate only merged protected-branch revisions. (2) A separate attestation service holds the signing keys and signs `(OpKey, ObjectId)` only for jobs dispatched to trusted builders, bound to workload identity. (3) Release gates and every `SignOff` Check accept a cached result only when two independent trusted builders produced the same `ObjectId` (different hosts; for `Portable` operations, different ISAs); otherwise they recompute. (4) Only the operator's own fleet writes the global public domain, with 2-of-n agreement. The default client trust policy is "own organization plus operator public signers". (5) Weight spot re-execution by downstream fan-out, at 100% for nodes that feed released Checks. (6) Hardware runners sign measurements with TPM-held device keys under measured boot. Reword contract §7.1 to: "Only trusted builders evaluating trusted inputs write the shared cache."

### R5-04 · Critical · Targets: AGT, UIX, KLN, CONTRACT
**Section:** AGT Irreversible real-world actions (D-AGT-20), MCP profile; UIX Approving and rejecting, Approvals, Platforms and devices
**Problem:** D-AGT-20 claims "the approval never passes through the agent's channel", but the approval URL does: the client presents it, and without elicitation support it returns to the model in `context`. Because any "approver with the required authority" may approve, a hijacked agent, compromised host or insider can prepare a plan and forward its genuine Crucible URL to a busy approver. File names in `Effect::SendFiles` come from the plan's author, so the human approves a name while the digest names other content. There are three approval surfaces (UIX's "secure dialog", AGT's approval page, the planned MCP Apps viewer inside the host), and phones may approve although the contract makes them viewers.
**Evidence:** MCP: "URL mode elicitation returns a URL that an attacker can use to send to a victim. The MCP Server **MUST** verify the identity of the user who opens the URL before accepting information." (https://modelcontextprotocol.io/specification/2026-07-28/client/elicitation). AGT: "A client that does not support elicitation receives `act.approval_pending` with the approval URL in `context`"; "Approval requests reach the delegating human, or an approver with the required authority". UIX: "explicit human confirmation through the platform's secure dialog"; "The phone app shows saved views, comments, approvals". Contract §9: "phones as viewers".
**Fix:**
1. Make an approval request a server record assigned to named approvers by Cedar policy, delivered only to their Crucible inbox. Push notifications carry no content. Anyone else who opens the URL sees "not assigned to you".
2. Never return the approval URL to the model; `act.approval_pending` carries only a request id.
3. The server generates the approval page: file names from item number, revision, format and release tag; a server-rendered thumbnail; a content summary (Items, labels, bytes); the recipient's verification and screening dates; a diff against the last approved plan of the same class to the same recipient; and the session `purpose`, marked as agent text.
4. Require phishing-resistant WebAuthn user verification. R4 classes can be approved on desktops and tablets only.
5. Allow at most 3 pending requests per session. A denial blocks re-preparing a plan to the same recipients for 24 h and offers "report as suspicious", which freezes the session.
6. Reject invisible characters, Unicode tag characters (U+E0000 to U+E007F), bidirectional controls and zero-width characters in free-text payloads (`notify_external`, RFQ notes).
7. Make the MCP Apps viewer read-only, and make UIX's secure dialog this same page.
8. Extend O-AGT-9: approvals from a forwarded URL by a non-assignee, plan substitution, hidden characters and approval spam are all refused.

### R3-32 · Major · Targets: ING, KLN
**Section:** ING "Lossless syntax tree" (block table), D-ING-18; KLN "CRDT over the syntax tree"

### R3-33 · Major · Targets: ING, PLT, KLN

### R5-41 · Minor · Targets: KLN
**Section:** KLN IP protection (D-KLN-31)
**Problem:** A remote parametric model returns Bodies for any parameter values, so a recipient can sample the parameter space and reconstruct the design intent the share was meant to protect. No quota, range limit or audit rule bounds this.
**Evidence:** KLN: "A feature callable with parameters; evaluation runs on the owner's workers, and results return as Bodies".
**Fix:** Each remote parametric share declares per-recipient query budgets, allowed parameter ranges and step sizes, and optional output simplification within a declared deviation. Every query is audited. A query over budget returns `ShareQuotaExceeded`.

### R6-44 · Minor · Targets: KLN, PLT
**Section:** KLN The CAS, Hashing (D-KLN-14); PLT The browser target, Storage
**Problem:** SHA-256 compiled to wasm32 has no SHA instructions, so browser hashing runs several times slower than native, and the 1 GiB in 150 ms target has no browser counterpart. Browsers offer native SHA-256 in workers.
**Evidence:** MDN `SubtleCrypto.digest`: "available in Web Workers", supports SHA-256, "returns a Promise", and "does not support streaming input".
**Fix:** The browser CAS hashes each chunk (≤ 1 MiB, already independent under D-KLN-15) with `crypto.subtle.digest` from the engine worker and combines chunk digests through `Index` nodes; state a browser target (for example 1 GiB in ≤ 1 s with 8 workers), and keep the Wasm SHA-256 for small synchronous objects.
