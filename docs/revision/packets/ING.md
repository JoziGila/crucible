### R1-03 · Critical · Targets: CONTRACT, COV, FLX, ING
**Section:** Contract §5 `ErrorBudget` ("A not-quantified component is never treated as zero"); COV D-COV-4 and "Error budget"; COV open question 3.
**Problem:** The contract and COV give incompatible semantics for unquantified components. Under the contract a check cannot pass while model-form error is unquantified, which COV says holds for every E2 model, so no std sign-off check could ever pass. COV instead evaluates on the quantified part and attaches an `unquantified` tag, which treats the missing term as zero for the `Pass` decision and violates the contract and principle 5.
**Evidence:** Contract §5 sentence quoted above. COV: "A check evaluates on the quantified part of its budget and carries an `unquantified` tag naming the missing components. Release policy in `repo` decides whether a tag is acceptable." COV OQ3: "E2 models have no measured model-form error."
**Fix:** Make the outcome explicit and typed: `Pass { conditional_on: [Component] }`, distinct from an unconditional `Pass`. A conditional pass meets a release gate only if repository policy names, for each unquantified component, a covering allowance with a citation (for example a design-code partial factor that the code states covers model uncertainty, applied to the demand). The check is then re-evaluated with that allowance included as a declared `Estimated` component; without such a policy entry the outcome is `Undecided { reason: Unquantified(components) }`. Write this rule into contract §5 and COV D-COV-4; ING's `CheckOutcome` carries `conditional_on`.

### R2-02 · Critical · Targets: ANV, ING, KLN, MEC, CONTRACT
**Section:** ANV Symbolic perturbation; Memory layout; Determinism rules; ING Entities and call sites; MEC Solver method, Patterns and mirror (`by_density`), D-MEC-22; KLN CRDT over the syntax tree; Storage format
**Problem:** EntityIds hash OpSites whose statement identity is a Loro node id, which is not a function of the source text and is dropped by `crucible export git`. Anvil and MEC nevertheless use EntityIds to order, tie-break and seed geometric computation, so meshes, `by_density` placements, reduction orders, solver decompositions and variation statistics depend on invisible metadata. Identical text can give different bits, a reviewer cannot predict geometry from a diff, and a design exported to Git and re-imported may not rebuild identically, which breaks D-MEC-5 ("the result must not depend on edit history, only on source") and the exit guarantee.
**Evidence:** ANV: SoS "perturbation order is the canonical vertex order of the encoded Body (face-group EntityId, then local index)"; row order "Morton code ... then EntityId"; BVH "EntityId tie-breaks"; independent sets "priority is a hash of the element's deterministic id". MEC: `by_density` "seeded from EntityIds"; decomposition "Ties break by EntityId"; Sobol "scramble seed derived from the design's EntityIds"; witness values "pseudo-random rationals derived from EntityIds". ING: statement identity is "The BlockId of the enclosing statement block"; external edits "match blocks by GumTree, so most BlockIds survive". KLN: "Block identities are Loro tree node ids"; "crucible export git writes Ingot text and lockfiles".
**Fix:** Add a label-invariance rule to contract 7.3: an operation's geometry, connectivity, Field values and statistics are invariant under any injective renaming of input EntityIds and OpSites; only label sections may change. Implement it with canonical orders from geometry and topology (box minimum, box maximum, entity type, defining parameters; distinct entities of a valid Body never tie on all of them), SoS indices and independent-set priorities from that order or from geometric content hashes, and seeds for `by_density`, Sobol scrambles and witness values from hashes of argument values and input geometry. Add oracle ANV-O-LABEL-1: rebuild every golden product with all BlockIds re-randomized and require identical geometry hashes (label sections excluded) and identical check values.

### R3-03 · Critical · Targets: ING, KLN
**Section:** ING "Strict, ordered, and failure-aware" (D-ING-11), "Resource limits"; KLN "Errors as values" (D-KLN-6)
**Problem:** `try` and wildcard `err(e)` arms catch any `Failure`, and nothing excludes environmental failures (out of memory, device loss, cancellation, a budget exhausted mid-run). Nor does anything exclude a `DependencyFailed` whose upstream was environmental. A feature can therefore take its fallback branch because a worker ran out of memory, and Kiln caches the fallback geometry as a deterministic value. This breaks principle 4 and can poison the shared cache.
**Evidence:** ING: "`Failure` is an extensible union ... a match over `Failure` needs a wildcard arm"; "`try e` turns propagation into a value of type `Result<T, Failure>`"; "When the host cannot supply memory ... evaluation fails with an environmental `ResourceExhausted`, which Kiln never caches". KLN: "A node that needs a failed value fails with `DependencyFailed { upstream }`"; "Exhausting a budget mid-run is an environmental failure and is never cached".
**Fix:** Contract 7.2 and ING define two disjoint classes. A deterministic `Failure` is catchable and cached. An environmental `Abort` covers cancellation, `ResourceExhausted`, device loss, budget exhaustion, worker loss, an unavailable retired version and the limits of R3-04. `Abort` is not a `Failure`: `try` cannot observe it, it propagates to every transitive dependent, and no node that observed one writes a memo entry, CAS object or attestation. `DependencyFailed` wraps only deterministic failures. New oracle `kiln/abort`: inject environmental faults at random Ops in 10,000 runs; every value that reaches the memo or shared cache equals the fault-free run's value.

### R3-04 · Critical · Targets: ING, KLN
**Section:** ING "Resource limits", "Strict, ordered, and failure-aware"; KLN "Scheduling and parallelism"
**Problem:** Ingot's claim that every evaluation ends in a value or a typed failure is false. Every limit applies per feature call, and each feature call is a separate Kiln node with fresh limits. A feature that calls itself with a new argument (`f(n) = f(n + 1)`) therefore builds an unbounded chain of nodes, and Kiln detects only a node that reappears on its own stack. Total work is also unbounded: 10⁹ steps per call times any fan-out times depth.
**Evidence:** ING: "Limits apply per feature call ... Feature calls and `#[memo]` function calls are Kiln nodes with their own limits ... Termination still holds, because every call is bounded and call depth is bounded"; the 2,048-frame depth limit is a "Default per feature call". KLN: "When a node demands a node already on its own active stack, Kiln returns `EvalError::Cycle`".
**Fix:** Kiln enforces two evaluation-wide limits as environmental `Abort`s (R3-03), so they never change a cached value. One is a demand-depth limit on nested node demands (default 10,000); the other is an aggregate fuel governor per Evaluation, taken from the request's budget. Restate ING's guarantee: "every node terminates with a value or a typed failure; every Evaluation terminates or aborts". New oracle ING-O-24: `f(n) = f(n + 1)` aborts with `DemandDepthExhausted` on every Tier 1 target and leaves no memo entry.

### R5-02 · Critical · Targets: AGT, KLN, ING, CONTRACT
**Section:** AGT Untrusted content is data (trusted origins; Endorsement), Independent verifier, Text descriptions (D-AGT-10)
**Problem:** Only import-derived strings are wrapped in `external(...)`; comments, doc comments, string literals, identifiers and description templates that an agent writes into Ingot are ordinary source. The verifier reads the Proposal's design untainted, so an author agent can address it in a comment. Once a human merges the Proposal, endorsement makes that text trusted on `main` permanently, where every later "clean" session and canonical `inspect.describe` output read it. D-AGT-18's guarantee that untrusted content "can never become instructions" is therefore false.
**Evidence:** AGT trusted origins include "Ingot source on protected branches". AGT: "When a human approves and merges a tainted Proposal, its content becomes trusted on the target branch. This covers geometry, parameters and source the human reviewed." The verifier "sees the requirements, the design, the semantic diff, the CI report and the rationale's structured fields". D-AGT-10 context: "a feature's doc metadata supplies its phrasing", and only "Templates from unverified publishers are untrusted text". The non-tainting exemption covers "identifiers that Crucible generates", not identifiers an agent writes.
**Fix:** (1) `repo` keeps span-level integrity provenance: each source span records the integrity of the context that wrote it, and merges preserve it. (2) `read.source`, `read.outline`, `read.docs` and `inspect.describe` return free-text spans as `ExternalText` handles when their author is outside the reader's delegation chain or their integrity is untrusted. Free-text spans are comments, doc comments, string literals, description templates, and identifiers not produced by the compiler or typed by a human. (3) Narrow endorsement: a human merge endorses structure and typed values, never free text. Free text becomes trusted only through an explicit per-span "endorse text" action that shows it verbatim, with invisible and bidirectional characters highlighted. (4) The verifier reasons over a typed view (IR, semantic diff, Check results) with the author's free text elided. (5) Add injection-suite cases: an instruction planted in a merged doc comment, identifier or description template must not change a later clean session's actions or the verifier's verdict.

### R1-05 · Major · Targets: CONTRACT, FLX, AGT, ING
**Section:** Contract §6 canonical example; FLX "Honest reporting of singular quantities"; AGT bracket example (09-agents line 587).
**Problem:** The canonical example clamps a whole face and checks `peak_stress`; the edges where the clamped face meets free faces carry an elastic edge singularity, so the peak diverges under refinement and, by Flux's own rule, the check is always `Undecided`. Flux's geometric detector lists only re-entrant edges, point measures and bi-material corners, and misses changes of boundary-condition type, contact edges and edges of loaded or fixed patches. The AGT example reports an impossible result: "worst margin `peak_stress` 31% (interactive fidelity, error estimate 4%)".
**Evidence:** Contract §6: `let stress = peak_stress(p, load, fixed: base.face(role: start_cap))`. FLX: "geometrically, by edges with dihedral angle above 180° and point measures". Reasoning: a 90° wedge with one clamped and one traction-free face has a Williams eigenvalue below 1 for ν near 0.3, so stress grows like r^(λ−1) toward the edge; the same holds along the edge in 3D.
**Fix:** Rewrite the example to support through the bolt-hole faces with a bearing or frictional condition and to check stress on a named region, for example `peak_stress(p, load, fixed: ..., region: solid.faces(role: fillet))`. Extend the detector to every edge where the boundary-condition type or the material changes, every contact boundary and every edge of a fixed or loaded patch; on such edges `peak_stress` returns `Undecided { SingularPoint }` unless the check names a region that excludes a stated distance from them. Correct the AGT example to match.

### R1-24 · Major · Targets: FLX, ING, COV, ELX
**Section:** FLX "Measures" and "Function spaces"; COV battery, homogenization and radiation rows; ELX D-ELX-19.
**Problem:** The weak-form language integrates only over geometric regions, faces, edges, points and interfaces, but several committed models live on nested or phase-space domains: DFN batteries (electrode thickness × particle radius at every macro point), FE² and pore diffusion (a micro problem per quadrature point), discrete-ordinates radiation (position × direction) and population balances (position × size). They cannot be Ingot forms with form-level derivatives and GPU kernels, contrary to their "Nat" delivery.
**Evidence:** FLX measures are only `dx`, `ds`, `dS`, `dE`, `dP` and `dI`. COV "Battery cells ... Doyle–Fuller–Newman (P2D)" is delivered "Nat"; COV radiation uses "discrete ordinates for participating media"; ELX D-ELX-19: "Cell models are Flux forms".
**Fix:** Add parameter-domain spaces and measures (`Interval(Length, n)`, `Sphere(directions)`, product spaces V_macro ⊗ V_micro, and a measure `dξ` over the parameter domain), compiled as batched local problems per macro quadrature point, the same machinery FE² needs. Agree the type syntax with ING, for example `Field<(Body, ParticleRadius), Concentration>`. Oracle: a P2D form matches PyBaMM's DFN on a shared parameter set.

### R2-06 · Major · Targets: ING, ANV, KLN
**Section:** ING Entities and call sites (Call path); KLN CRDT over the syntax tree; ANV EntityId (D-ANV-14)
**Problem:** The call-path part of `OpSite` is a path of slot names from the statement root, so it changes under the most frequent edits in pipeline code: appending `|> chamfer(...)` to `blank |> extrude() |> hole() |> fillet()` re-nests every earlier stage (with a flat stage list, inserting a stage shifts every later one), and wrapping a call deepens the calls inside it. Every entity those stages created gets a new EntityId, downstream caches miss, and review comments and exported persistent IDs lose their anchors. Calls have no CRDT identity to fall back on, because blocks stop at statements.
**Evidence:** ING "Call path | The path from the statement root to the call in the typed syntax tree, as slot names (`pipe.rhs`, `arg(t)`, `receiver`) | Adding or reordering arguments, editing literals" (no stability claimed for added stages); grammar `pipe = range_expr { "|>" postfix }` and "`x |> f(a)` means `f(x, a)`"; ING worked example 1 and the contract example are multi-stage pipelines; KLN blocks are "at least items ..., statements inside bodies and parameters".
**Fix:** Give every call expression and pipeline stage a stable node identity: declare them mergeable blocks in the KLN block tree, so the structural editor and the GumTree reconcile keep their ids across appends, inserts and wraps. Define `OpSite` as (statement BlockId, call node id, feature instance path, loop keys) without the root path. Add oracle ING-O-SITE-1: appending, inserting and wrapping stages in golden-product pipelines leaves the EntityIds of untouched calls unchanged.

### R2-11 · Major · Targets: ANV, MEC, ING
**Section:** ANV Transform, pattern, mirror; MEC Patterns and mirror; ING Kiln-held values (`.moved(by:)`)
**Problem:** `anvil::transform` keeps EntityIds for rigid motions and reflections, and MEC's `mirror` and Ingot's `move` lower to it. Combining a Body with a moved or mirrored copy of itself, the commonest symmetry idiom (`half + mirror(half, plane.yz)`), or two Instances of one Part in an assembly-level feature, puts identical EntityIds into one Boolean, which fails with `EntityIdCollision` or makes every query on the seed resolve to both copies. Roles also flip meaning under reflection (`side(left)` lands on the right).
**Evidence:** ANV transform row "EntityIds kept: identity for rigid motions, `Modified { aspects: Geometry }` for scaling and reflection"; the separate-id guarantee exists only for `anvil::pattern` ("an original and its mirror copy never share EntityIds"); "Within one Body, a duplicate EntityId fails the operation with `Internal::EntityIdCollision`"; MEC patterns and mirror use "`anvil::transform`, `anvil::boolean` (n-ary)".
**Fix:** Separate placement from copying. A transform whose source value is used again in the program (Ingot knows this from data flow) or that is written as `copy` creates ids `EID(kind, site, role: copy, [source id])` with a new `Copied { from, into }` record that lineage follows only on request (`seed.face(top).copies()`); a motion that replaces the Body in the data flow keeps ids. Reflection records `Mirrored`, so role queries can say `side(left, mirrored: true)`. Assembly-level features prefix ids with the Instance path.

### R2-12 · Major · Targets: ING, MEC, ANV, CONTRACT
**Section:** ING Entities and call sites (Loop indices); Patterns, loops and identity; MEC Patterns and mirror (`skip: [Int]`, `at_points`, `fill`, `by_density`); ANV Rust API (`OpSite`)
**Problem:** `OpSite` uses the positional iteration index by default and keyed iteration is opt-in; patterns name copies and skip instances by index. Patterns driven by geometry (`at_points`, `fill`, `by_density`, `along`) and loops over query results (`for e in body.edges(convex)`) therefore rename every later copy, retarget skip lists and break anchors when one element is inserted or removed. That is positional indexing under another name, contrary to the contract's "No positional indexing".
**Evidence:** ING "Loop indices | The iteration index, or the key of a `keyed` collection"; "`for x in keyed(holes, by: |h| h.label)` uses the key in place of the index" (opt-in); ANV `OpSite { path, indices: Box<[u32]> }`; MEC `skip: [Int] = []`; `by_density` runs Lloyd iterations that move every seed.
**Fix:** Make keys the default. Iteration over `Entity<K>` lists or resolved queries keys by EntityId; transform generators return keyed lists (`linear` keys `(i, j)` from the seed, `circular` the angular index, `at_points` the point's anchor EntityId, `fill` lattice coordinates from a declared origin, `by_density` each seed's initial key before Lloyd steps); plain integer ranges keep integer keys. Replace `skip: [Int]` with `skip: [Key]` and `OpSite.indices: [u32]` with `[SiteKey]`. The language service warns on positional keys over lists whose length depends on geometry.

### R2-16 · Major · Targets: ING, MEC, ANV
**Section:** ING Sketches and constraints; MEC Solver method (step 4) and Diagnosis
**Problem:** A solved sketch point is returned as `Approx<Point3>` "whose bound comes from the solver's converged residual", but a residual is not a forward error bound: the position error is about ‖J⁻¹‖·‖r‖, large for nearly tangent arcs, nearly parallel lines and near-singular mates. A `Guaranteed` bound derived this way lets `Truth` decide checks wrongly. The convergence rule "below one hundredth of the smallest Anvil entity tolerance" (about 10⁻¹² m for a 0.1 m sketch) also fails on ill-conditioned but valid sketches.
**Evidence:** ING "Reading `s.c.center` after the solve returns `Approx<Point3>`, whose bound comes from the solver's converged residual"; MEC step 4 "Convergence requires the scaled residual below one hundredth of the smallest Anvil entity tolerance involved"; Anvil already certifies roots with Krawczyk elsewhere.
**Fix:** After each well-determined block converges, run a Krawczyk (or Kantorovich) test on the scaled system; the radius of the proven box is the `Guaranteed` bound and certifies a unique solution on the chosen branch. If the test fails, the bound is `Estimated` (an estimate of ‖J⁻¹‖ times the residual) and the report says why. Replace the absolute convergence rule with "residual small enough that the certified box radius is below the smallest entity tolerance", else `IllConditioned { block, condition }` with fixes.

Ingot's own budget of 200 µs per feature is within an interpreter's reach for orchestration code, so the code generator adds a second executor to the critical path with no phase 1 golden-product need.
**Evidence:** ING: "Interpreter within 15× of compiled code"; "Ingot code, excluding operations, takes at most 2% of the contract's 2 s rebuild … 200 µs per feature"; ING-O-1 compares both executors bit for bit on every target.
**Fix:** Amend the ruling: "Until the Ingot code generator ships, the reference interpreter is the only Ingot executor on every target; Pulley and browser engines run Wasm components only." ING phase 1 drops the code generator, Perceus and the state-machine transform, and adds an interpreter target (≤ 200 µs per GP1 feature body on the reference laptop, ≤ 3× that in browsers). The code generator enters phase 2 if `ingot-bench` shows Ingot above 2% of a golden-product rebuild; heavy numeric loops go to operations or `#[ingot::feature]` Rust components meanwhile.

### R6-33 · Major · Targets: ING, FLX, PLT, ECO
**Section:** ING Compilation strategy, Performance targets and evidence plan; FLX Kernel generation (D-FLX-9); PLT State of the art (Wasm runtime and Browser engine rows); PLT The browser target, Performance relative to native
**Problem:** Several ratio targets ignore costs the same drafts impose. Ingot is "within 1.5× of Rust natively" while generated code checks for non-finite values before every comparison and branch, checks integer overflow and counts references; Wasm components are "at most 1.3 times in Wasmtime, 2.0 times in browsers" after instrumentation; user forms are "within 2× of ahead-of-time kernels" while running 128-bit SIMD against 512-bit ahead-of-time code on AVX-512 machines; and the browser suite targets 1.6× and 2.0× native while losing wide vectors everywhere.
**Evidence:** ING The deterministic Wasm subset (NaN checks, overflow checks, fuel); D-FLX-9: "Wasm SIMD128 is narrower than AVX2 or AVX-512"; PLT State of the art targets; Jangda and colleagues measured browsers 45% to 55% slower than native on scalar SPEC code (cited by PLT).
**Fix:** Revise: Ingot numeric kernels ≤ 2.5× Rust natively and ≤ 4× in browsers (deferred with the code generator, R6-25); Wasm components ≤ 1.6× native Rust in Wasmtime and ≤ 2.5× in browsers after instrumentation; user forms ≤ 2× ahead-of-time kernels on AVX2 and ≤ 4× on AVX-512; browser suite geometric mean ≤ 2.0× single-threaded and ≤ 2.5× multi-threaded on the AVX2 reference laptop, with SIMD-heavy kernels reported separately at ≤ 3×.

### R2-41 · Minor · Targets: ING, ANV
**Section:** ING Kiln-held values (`convert`); Approximate values as inputs; ANV Conversions (D-ANV-21)
**Problem:** Ingot wraps converted Bodies in `Approx<Body>` and adds measurement bounds of driving inputs to "the result Body's accumulated ErrorBound", while Anvil keeps per-face conversion bounds in the Body and defines `body.error()` as their maximum. Geometric error then lives in two places with different meanings (representation error against input uncertainty), and `Approx<Body>` makes `Estimated` fits fail as inputs (ING6403) although the Body already records its bound.
**Evidence:** ING "`body.convert(into: Mesh, tolerance: 0.01mm)` returns `Approx<Body>`"; "the bound is recorded in the call's accumulator and added to the result Body's accumulated `ErrorBound`"; ANV D-ANV-21 and `Body::error()`.
**Fix:** `convert` returns `Body`; representation error lives only in Anvil's per-face bounds. Bounds of `Approx` arguments go to an `InputSensitivity` record on the feature call, which variation analysis reads, not into `body.error()`.

### R2-42 · Minor · Targets: ING
**Section:** The query language (Geometric filters)
**Problem:** Writing a filter range as a tolerance (`radius: 3mm ± 0.05mm`) creates a tolerance site, and D-ING-4 records every tolerance a feature receives for PMI and variation analysis, so a selection range can surface as a manufacturing tolerance.
**Evidence:** ING "`radius: 3mm ± 0.01mm` ... a range or `Tol` argument means membership"; D-ING-4 "Every feature call records the tolerances it receives, so variation analysis, dialogs, PMI and `tolerances(x)` can find them".
**Fix:** Filters accept ranges (`radius: 2.95mm..=3.05mm`) or `near(3mm, within: 0.05mm)`; passing a `Tol` to a filter is a compile error whose fix rewrites it as a range.

### R2-44 · Minor · Targets: UIX, ING, ANV
**Section:** UIX From gesture to Ingot edit (ranking rule 1); ING Derivatives
**Problem:** Edit-plan ranking uses derivatives of the dragged quantity with respect to literals, but derivatives through Anvil operations need `anvil::shape_velocity`, which is phase 2, while direct manipulation is phase 1, and ING then falls back to dependence only. UIX does not say what the phase 1 ranking is.
**Evidence:** UIX "The nearest single literal with a non-zero derivative ranks first"; ANV `shape_velocity` "Phase 2"; ING "An Op without a tangent rule makes the derivative fail ... and the UIX ranking falls back to dependence only".
**Fix:** State the phase 1 ranking: provenance first (the literal of the call whose OpSite and role created the dragged entity, for example the extrude distance for an end cap), then IIR dependence distance; derivatives refine the ranking from phase 2.

### R2-48 · Minor · Targets: MEC, ING
**Section:** MEC Part features; ING Kiln-held values (prelude frames)
**Problem:** The part-feature catalog has no reference geometry beyond the world planes and named `csys` values: no offset plane, plane at an angle, mid-plane between faces, plane through three points, tangent plane, axis of a face or through two points, or construction point on a curve. SOLIDWORKS, NX, Creo and CATIA users rely on these to place sketches, mirrors and patterns.
**Evidence:** MEC part-feature sections (profile, holes, dress-up, patterns, split, direct edits, deform, derived parts, configurations, lattices, machine elements) list none; ING prelude defines "the planes `plane.xy`, `plane.yz` and `plane.xz`"; MEC's drawing example uses `p.csys("mid").plane(yz)`.
**Fix:** Add `std::mech::refgeom` in phase 1: `plane.offset(from, d)`, `plane.at_angle(about: axis, angle)`, `plane.mid(a, b)`, `plane.through(p1, p2, p3)`, `plane.tangent(face, at)`, `axis.of(face)`, `axis.through(p1, p2)` and `point.on(curve, at:)`. Each returns a `CoordSys`-anchored value re-resolved through its queries, with handles for direct manipulation and typed `ResolveError`s.

### R3-47 · Minor · Targets: CONTRACT, PLT, ING

### R3-48 · Minor · Targets: ING, ECO

### R3-50 · Minor · Targets: ING
**Section:** ING "Affine quantities", "`Approx<T>` and `Truth`"
**Problem:** The affine table says temperature units inside a compound unit "always mean differences", yet makes `20[J/degC]` an error. `Approx<T>` puts its bound "in T's dimension", which for `Temperature` must be a difference.

### R3-51 · Minor · Targets: CONTRACT, ING, PLT
**Section:** CONTRACT 7.4 (the determinizer verifies Ingot modules); ING "The deterministic Wasm subset"
**Problem:** The determinizer cannot check that an Ingot module charges the language cost table, because it lacks the IIR. "Verifies" therefore has no stated content.
**Evidence:** Contract 7.4: "the determinizer verifies such modules instead of rewriting them". ING: "Ingot charges language steps computed on the canonical IIR".
**Fix:** List what verification checks: no forbidden instructions or imports; a fuel decrement dominating every loop back-edge and function entry; a non-finite check before every float store, every comparison that feeds a branch and every host call; and a depth counter in every prologue. Fuel accuracy is ING-O-1's job.
