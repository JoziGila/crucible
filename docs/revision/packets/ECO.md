### R2-21 · Major · Targets: ANV, ECO
**Section:** ANV Names for other representations (Imported B-rep); `anvil::match_bodies`; ECO Identity across round trips
**Problem:** The two tabs give imported entities incompatible identities: Anvil uses a quantized geometric signature, ECO uses the source's persistent ID or "assembly path plus entity ordinal". Ordinals are positional and change when a supplier re-exports, and quantized signatures flip at quantization boundaries. `match_bodies` pairs faces by Hausdorff distance and overlap, so exactly the faces a supplier moved fail to match, and the mapping it produces is not reviewable.
**Evidence:** ANV "the discriminator is a geometric signature (surface type, quantized defining parameters and box at the face tolerance)"; "pairs faces by certified Hausdorff distance and overlap in the shared coordinate frame"; ECO "Otherwise the role is the structural path (assembly path plus entity ordinal), which is weaker".
**Fix:** One rule, owned by ANV and cited by ECO: imported EntityId = EID(kind, import site, role `imported`, [], discriminator), with the discriminator taken in order from the source persistent ID (AP242 persistent IDs, IFC GlobalId, native ids exposed by licensed translators), else an unquantized canonical signature (surface type plus a hash of the exact defining parameters as written) plus an adjacency signature, never an ordinal. `match_bodies` aligns rigidly first (`anvil::align`), then matches the attributed face-adjacency graph (type, area, normals, neighbors), and writes the confirmed mapping as a source artifact (`import_map(old, new, pairs)`) that reviewers see and later rebuilds reuse.

### R2-28 · Major · Targets: ECO, ANV
**Section:** ECO Round-trip and differential suites; Identity across round trips; ANV Cellular topology (no seam, no degenerate edges), D-ANV-7
**Problem:** Two oracle pass lines cannot pass by construction. Anvil forbids seam edges and degenerate pole edges and keeps procedural surfaces (blends, sweeps, intersection curves) that AP242 receivers get only as B-spline approximations, so a self round trip cannot give "B-rep surfaces and curves bit-identical; same topology counts". OCCT's B-rep stores seam edges on closed periodic faces and degenerated edges at poles, so a differential read cannot give "Topology counts equal". Receivers that expect seams also need them on export, while Anvil writes seams only "where the target schema requires them".
**Evidence:** ECO "Self round trip | ... B-rep surfaces and curves bit-identical; same topology counts"; "Differential read | ... Topology counts equal"; ANV "No seam edges", "No degenerate edges", "STEP export inserts seams where the target schema requires them"; D-ANV-7 procedural geometry.
**Fix:** Define a topology normal form for comparisons (seams and poles removed, periodic faces unsplit, seam and pole counts reported separately) and apply it to both sides. Self round trip: analytic and NURBS geometry bit-identical; procedural geometry equal to its recorded B-spline approximation within the stored bound; topology equal in normal form. Export always writes seam edges and pole vertices, configurable per receiver profile, and records them in the translation report so persistent IDs map back to Anvil entities.

### R3-06 · Major · Targets: ING, KLN, ANV, ECO, CONTRACT
**Section:** ING "Entities and call sites"; KLN "CRDT over the syntax tree", "Storage format"; ECO "Package registry"; CONTRACT 5 (`EntityId`)
**Problem:** `OpSite`, and so every entity name, depends on Loro node ids that cannot be derived from source text. The same text can get different names after a Git round trip, after re-typing a statement, and in a registry package. ECO publishes packages without block maps, so ING's ordinal fallback applies to them. Inserting one statement into a std feature then renames entities in every dependent design on upgrade.
**Evidence:** ING: statement identity is "The `BlockId` of the enclosing statement block in the live document"; "A file outside any repository ... gets `BlockId`s derived from item paths and statement ordinals"; an outside edit "matches blocks by GumTree, so most `BlockId`s survive". **Fix:** Define statement identity from text in ING and contract 5. A `let` statement's identity is (item path, arm path, binding name), which ING1102 already makes unique per block. An unnamed statement's identity is (item path, arm path, nearest preceding binding name, ordinal after it). Renaming a binding is a refactor that writes `#[was(old_name)]`, which preserves the identity until the next edition. Loro node ids map onto these identities for collaboration only and never enter `OpSite`. New oracle (ING-O-10 and ANV): export to Git, re-import and rebuild; every `EntityId` is unchanged.

**Evidence:** ECO: "A `quote-request` names a release by its signed tag and carries content-addressed Files ... Orders are Acts" (RFQs are not). Contract §7.6: "publish, yank and export are Acts". ECO: Git mirror is "A one-way export of the Ingot sources, manifests and lockfiles to a Git repository". KLN: suppliers return feedback as "a Proposal on a branch shared with them".
**Fix:** Route every byte leaving a tenant through one Act family, `release_data { recipient, payload, purpose, authorization }`. Every member runs the same checks at commit:
- labels against recipient attributes;
- restricted-party screening;
- for `export_controlled`, an export authorization record (license number, license exception or exemption);
- a watermark record, expiry and audit.

ECO states that `request-quote` runs only inside a `request_quote` Act, and that the Git mirror, `archive.export` and passport publication are Acts. Branches shared with external organizations are external surfaces: agent writes there need `share_external` and are refused to tainted contexts.

### R5-09 · Major · Targets: ECO, PLT, KLN
**Section:** ECO Running on every platform; PLT Wasmtime configuration, Open questions (6); KLN Distributed and remote evaluation
**Problem:** Third-party evaluation components from verified publishers run inside the engine process. That process holds every open repository and the user's tokens and can use the device signing key, so Wasmtime is the only boundary. Wasmtime's 2026 advisories include an out-of-bounds write in Component Model string transcoding and data leakage between pooling-allocator instances, and PLT uses the pooling allocator. ### R5-10 · Major · Targets: ECO
**Section:** ECO Signing, provenance and transparency (D-ECO-16), Manifest and lockfile
**Problem:** Clients check that a package is Sigstore-signed, but they learn from the registry which identities may publish to a namespace. A compromised registry can therefore authorize its own identity and publish versions that every client accepts at the next update. ECO also overstates TUF: with online registry keys, TUF does not survive a compromise of the registry itself.
**Evidence:** ECO: "The Update Framework, which keeps update systems secure even when the repository or signing keys are compromised". ### R5-12 · Major · Targets: ECO, PLT
**Section:** ECO Running on every platform (D-ECO-10); PLT Formats per target, In the browser
**Problem:** In the browser, every component ships with registry-generated JavaScript glue that runs in the engine worker's origin, where it can reach OPFS (every local repository), authenticated `fetch` and WebCrypto keys; the glue, not Wasm, is the real boundary. ### R5-14 · Major · Targets: ECO

### R6-20 · Major · Targets: PLT, ECO, CONTRACT

**Problem:** The determinizer inserts a NaN check after every floating-point instruction that can produce a NaN, scalar and SIMD, which is the approach Wasmtime says "adds overhead to Wasm's floating-point instructions"; in float-SIMD code it adds two or three instructions per arithmetic instruction. ### R5-40 · Minor · Targets: KLN, ECO
