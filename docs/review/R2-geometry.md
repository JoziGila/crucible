# R2 geometry review

Summary: (1) The kernel's determinism has two holes: tolerance growth changes shared state during parallel pair decisions, and canonical orders, perturbations and seeds use EntityIds built from hidden CRDT BlockIds (R2-01, R2-02).
(2) Several guarantees are false as written: per-face error bounds "inherited" through offsets, blends and intersections; validity checked only near changed entities; and a freedom-to-operate argument that ignores the patent's broader claim 16 (R2-03 to R2-05).
(3) Phase 1 modeling will not meet its wedge or its targets: blends fail on common corners and on earlier fillets, naming is positional for pipeline stages, loops and patterns, and the 2 s rebuild, 100 ms preview and mesh-Boolean targets contradict the chosen methods (R2-06 to R2-13).

### R2-01 · Critical · Targets: ANV
**Section:** Numbers, tolerances and predicates › Certified decisions; Kernel rules (rule 8); Surface-surface intersection (fuel); Performance, parallelism and determinism › Determinism rules
**Problem:** Tolerance growth (step 4 of the decision rule, near-miss "touch" decisions, merged entities taking the larger tolerance) changes per-entity tolerances that later decisions in the same operation read, while SSI, imprint and merge decisions run in parallel over pairs. The outcome then depends on which pairs are decided first, and a memoized "separated" answer can contradict a tolerance grown afterwards. Determinism fails on exactly the near-degenerate inputs the tolerance model exists for.
**Evidence:** "Anvil declares coincidence and grows the entities' tolerances to hi"; "It is deterministic because the enclosure computation has a fixed operation order" (this covers one enclosure, not the set of decisions); "success and output do not depend on the order in which pairs are processed"; rule 8 "every predicate about a pair of entities is computed once and memoized". Parasolid orders these decisions on purpose: its imprint phase compares lower-dimension entities first (vertex–vertex, then vertex–edge, edge–edge) and grows local tolerances as it goes (Jackson 1995, https://ftp1.cs.wisc.edu/pub/users/prem/jackson-SM-95.pdf, opened).
**Fix:** Add to "Certified decisions": decisions run in rounds by dimension (vertex–vertex, vertex–edge, edge–edge, edge–face, face–face). Within a round every candidate pair is decided in parallel against tolerances frozen at the round's start; growth requests are reduced per entity by max (order-free) and applied at the round's end; pairs touching a grown entity are re-decided in the next round until a fixed point (monotone and capped by τ_cap, so it terminates), otherwise `ToleranceCascade { entities, rounds }`. Memoize predicates by (pair, tolerance epoch). Add oracle ANV-O-DET-2: chains of three or more entities spaced at τ ± ρ/2⁹, evaluated with shuffled pair orders and 1 to 64 threads, give identical bits.

### R2-02 · Critical · Targets: ANV, ING, KLN, MEC, CONTRACT
**Section:** ANV Symbolic perturbation; Memory layout; Determinism rules; ING Entities and call sites; MEC Solver method, Patterns and mirror (`by_density`), D-MEC-22; KLN CRDT over the syntax tree; Storage format
**Problem:** EntityIds hash OpSites whose statement identity is a Loro node id, which is not a function of the source text and is dropped by `crucible export git`. Anvil and MEC nevertheless use EntityIds to order, tie-break and seed geometric computation, so meshes, `by_density` placements, reduction orders, solver decompositions and variation statistics depend on invisible metadata. Identical text can give different bits, a reviewer cannot predict geometry from a diff, and a design exported to Git and re-imported may not rebuild identically, which breaks D-MEC-5 ("the result must not depend on edit history, only on source") and the exit guarantee.
**Evidence:** ANV: SoS "perturbation order is the canonical vertex order of the encoded Body (face-group EntityId, then local index)"; row order "Morton code ... then EntityId"; BVH "EntityId tie-breaks"; independent sets "priority is a hash of the element's deterministic id". MEC: `by_density` "seeded from EntityIds"; decomposition "Ties break by EntityId"; Sobol "scramble seed derived from the design's EntityIds"; witness values "pseudo-random rationals derived from EntityIds". ING: statement identity is "The BlockId of the enclosing statement block"; external edits "match blocks by GumTree, so most BlockIds survive". KLN: "Block identities are Loro tree node ids"; "crucible export git writes Ingot text and lockfiles".
**Fix:** Add a label-invariance rule to contract 7.3: an operation's geometry, connectivity, Field values and statistics are invariant under any injective renaming of input EntityIds and OpSites; only label sections may change. Implement it with canonical orders from geometry and topology (box minimum, box maximum, entity type, defining parameters; distinct entities of a valid Body never tie on all of them), SoS indices and independent-set priorities from that order or from geometric content hashes, and seeds for `by_density`, Sobol scrambles and witness values from hashes of argument values and input geometry. Add oracle ANV-O-LABEL-1: rebuild every golden product with all BlockIds re-randomized and require identical geometry hashes (label sections excluded) and identical check values.

### R2-03 · Critical · Targets: ANV, CONTRACT
**Section:** Conversions (D-ANV-21); contract section 5 `Body`
**Problem:** The rule that faces "derived from bounded faces (offsets, blends) inherit the largest bound of their sources" is false, so `body.error()` and checks such as `body.error() < 10µm` can report `Guaranteed` bounds that do not hold. A Hausdorff bound δ says nothing about normals, so a normal offset by d may move by δ + d·(normal error); intersection edges and blend spines between approximated supports move by about δ/sin θ for supports meeting at angle θ, unbounded near tangency; Natural offsets amplify by 1/sin(θ/2) at corners.
**Evidence:** ANV "faces derived from bounded faces (offsets, blends) inherit the largest bound of their sources" and "A Check can therefore require `body.error() < 10µm`"; contract "Approximating conversions record per-face Hausdorff bounds that compose and survive later operations"; the draft's own tangency estimate √(2ε/Δκ) shows the amplification.
**Fix:** Make the per-face bound `{ position: ErrorBound, normal: angle bound }`, produced by every approximating conversion (fits certify both). Give each derived construction a propagation rule with certified conditioning: normal offsets `position + |d|·normal`; intersections, spines and contact curves `position / sin θ_min`, with θ_min a certified lower bound of the angle between the surfaces along the edge; Natural-offset corners `1/sin(θ/2)`. When θ_min is not bounded away from zero, the face bound is `Unknown`, which `Truth` treats as undecided. Amend the contract to "compose by stated propagation rules with certified conditioning, or become Unknown". Add oracle ANV-O-CONV-2: perturb approximated supports within their bounds and verify derived faces stay within the propagated bound on near-tangent blends and intersections.

### R2-04 · Critical · Targets: ANV, CONTRACT
**Section:** GPU strategy and freedom to operate (D-ANV-17); Open questions 2; contract section 13 (phase 0 freedom-to-operate gate)
**Problem:** The design-around analyses claim 1 (point-to-point distances) and the system claim only. Independent claim 16 of US 12,229,885 B1 needs neither a GPU nor samples of the second surface: it covers intersection points formed from first-surface points lying within a threshold distance of the second surface, however that distance is measured. Anvil's CPU path forms touches, coincidence regions and traced points on one surface within τ of the other, so "The CPU path is complete on its own, so an adverse opinion removes acceleration, never function" is unsupported reassurance about the core SSI.
**Evidence:** Google Patents (https://patents.google.com/patent/US12229885B1/en, opened): claim 16 derives a set of points representing the first surface from its description and forms intersection points from those "distanced from the second surface by less than a threshold distance"; claim 16 recites no GPU or parallel processor; claims 1, 6, 11 and 16 all rely on a threshold. ANV: "Near-miss closer than τ ... Treated as a touch"; "Pairs whose distance enclosure stays below τ over a region become coincidence regions".
**Fix:** Delete the sentence about acceleration and the claim-1-only argument. Rewrite open question 2 and the phase 0 item: counsel reviews claims 1, 6, 11 and 16 against both the GPU and the CPU path, with an invalidity search (sampled SSI with thresholds predates 2024; Krishnamurthy et al. 2008 is already cited). Record the technical distinction the design relies on: intersection points are certified roots of the exact equations (Krawczyk, implicit-function tracing), never points selected from a sampled set by a distance threshold, and tolerance decisions classify certified enclosures. Until the opinion arrives, treat SSI itself, not only GPU acceleration, as a phase 1 release risk.

### R2-05 · Critical · Targets: ANV
**Section:** Operation contract › What every operation guarantees (Validity); Formal semantics of a toleranced Body
**Problem:** Operations check validity only on created or modified entities and their neighbors, "which suffices because untouched entities were valid". Separation (condition 2) is pairwise and global, so an offset, moved, drafted, thickened or shelled face, or a large blend, that crosses a distant untouched face passes the check and is returned, cached and shared as valid. This is the commonest failure of local operations, and it surfaces later, far from its cause.
**Evidence:** "Operations run `check_body` on the entities they created or modified and on their neighbors, which suffices because untouched entities were valid and did not change"; separation is stated "For any two entities x and y".
**Fix:** Replace the sentence with: "Operations check incidence, combinatorics and regularity on created and modified entities and their neighbors, and check separation of every created or modified entity against all entities of the Body through the BVH broad phase (O(m log n) for m changed entities)." A clash returns `SelfIntersecting { faces, at }` with the operation's fixes. Add oracle ANV-O-VALID-2: offset_faces, move_faces, draft, shell, thicken and blend corpora with planted far-field clashes are all rejected.

### R2-06 · Major · Targets: ING, ANV, KLN
**Section:** ING Entities and call sites (Call path); KLN CRDT over the syntax tree; ANV EntityId (D-ANV-14)
**Problem:** The call-path part of `OpSite` is a path of slot names from the statement root, so it changes under the most frequent edits in pipeline code: appending `|> chamfer(...)` to `blank |> extrude() |> hole() |> fillet()` re-nests every earlier stage (with a flat stage list, inserting a stage shifts every later one), and wrapping a call deepens the calls inside it. Every entity those stages created gets a new EntityId, downstream caches miss, and review comments and exported persistent IDs lose their anchors. Calls have no CRDT identity to fall back on, because blocks stop at statements.
**Evidence:** ING "Call path | The path from the statement root to the call in the typed syntax tree, as slot names (`pipe.rhs`, `arg(t)`, `receiver`) | Adding or reordering arguments, editing literals" (no stability claimed for added stages); grammar `pipe = range_expr { "|>" postfix }` and "`x |> f(a)` means `f(x, a)`"; ING worked example 1 and the contract example are multi-stage pipelines; KLN blocks are "at least items ..., statements inside bodies and parameters".
**Fix:** Give every call expression and pipeline stage a stable node identity: declare them mergeable blocks in the KLN block tree, so the structural editor and the GumTree reconcile keep their ids across appends, inserts and wraps. Define `OpSite` as (statement BlockId, call node id, feature instance path, loop keys) without the root path. Add oracle ING-O-SITE-1: appending, inserting and wrapping stages in golden-product pipelines leaves the EntityIds of untouched calls unchanged.

### R2-07 · Major · Targets: ANV, MEC, CONTRACT
**Section:** ANV Blends (parameter and stage tables), State of the art (Blends); MEC Dress-up features; contract 7.1 (blends as a research program)
**Problem:** Phase 1 blending is constant radius with `KeepEdge` overflow and equal-radius three-edge corners on "analytic and NURBS supports"; blends whose supports are earlier blends wait for phase 4, yet the default overflow is `RollOver` (stage 2). Phase 1 users will fail on unequal radii at a corner, mixed-convexity corners (a boss-base fillet meeting a vertical-edge fillet), vertices of valence four or more, fillets that must roll onto a neighbor, filleting the top loop after the vertical edges, chamfer-fillet corners, chains across smooth edges and variable radius. OCCT, the open reference the draft benchmarks against, already offers linear and law-driven radii on tangent chains with corner fills.
**Evidence:** ANV stage 1 row; `overflow` default `RollOver`; stage 4 "Blends on blends (rolling over earlier blends)"; MEC `overflow: Overflow = Auto`; ANV target "above OCCT 8.0's at stage 1" versus MEC "target 97% success at phase 2"; OCCT `BRepFilletAPI_MakeFillet` reference (https://occt3d.com/dev/doc/refman/html/class_b_rep_fillet_a_p_i___make_fillet.html, opened): `Add(R1, R2, E)` sets "a linear radius evolution law", `Add(L, E)` takes a law, `Add(E)` "builds a contour of tangent edges", failed corners are reported per vertex.
**Fix:** Re-scope stage 1: supports include Anvil's procedural blend, offset and swept surfaces, so sequential fillets work; `RollOver` overflow; valence-3 corners with unequal radii and mixed convexity by setback patches; chamfer-fillet corners; termination at smooth edges; linearly varying radius. Leave valence ≥ 4, Field-driven radii and G2/G3 sections to later stages and amend the contract's ordering to match. Until `RollOver` ships, both tabs default to `KeepEdge`. Build the blend benchmark in phase 0 (recognize and remove fillets on ABC parts, re-fillet with the recorded radii) and state one target per phase in both tabs.

### R2-08 · Major · Targets: ANV
**Section:** Tangential and degenerate cases; Surface-surface intersection; Blends
**Problem:** Every rolling-ball blend is tangent to its supports along its contact curves, so later Booleans, offsets, shells, drafts and second fillets near blended regions meet tangential contact along curves on most real parts. The draft gives no algorithm beyond "Curve classified `Tangential`; Booleans treat both sides with the tolerance rule". The critical-point Krawczyk system is singular along such curves, and the band where |distance| < τ around a contact has width about 2√(2τ/Δκ), which the tolerance rule would turn into spurious coincidence regions.
**Evidence:** ANV tangential-cases table; "Tangential intersections are ill conditioned ... √(2ε/Δκ)"; blend history records only `Modified { aspects: Boundary }` for supports, with no tangency certificate on the contact edges.
**Fix:** Record construction certificates on edges, `Continuity { order: G1 or G2, certified_by: (operation, site) }`, for blend contact edges, offsets of smooth edges and sweep seams. SSI and imprint consult them: face pairs sharing a certified G1 edge are not re-intersected along it, and a new surface tangent to a blend goes to a contact-curve algorithm that traces the reduced system (the critical-point system with the rank-deficient direction removed and h = 0), certifies it with an interval test, and imprints one tangential edge with τ = max(ρ, certified contact deviation). Add oracle families: fillet on fillet, cylinder resting on a plane, sphere in a cylinder, blend face cut by a plane through its contact curve.

### R2-09 · Major · Targets: ANV, KLN, PLT, UIX, MEC
**Section:** ANV Performance targets, Fidelity levels; MEC Performance budget; UIX Coarse-first preview pipeline; ING Previews, drags and incomplete code; PLT Budgets
**Problem:** The 2 s exact rebuild of a 200-feature part after an early edit and the 100 ms coarse preview "with dependent features updated" are not supported by any mechanism in the drafts. After an early edit every downstream input changes, so MEC's read sets and tool-body caching save nothing and drag specialization's forward slice is the whole chain; 1.2 s for about 200 certified operations leaves about 6 ms each for certified SSI and marching, `check_body`, relabeling and Merkle hashing, while Anvil expects certified SSI at up to twice OCCT's time. Coarser preview tolerances do not reduce the number of B-rep operations, and Anvil defines no geometry fidelity between `Preview` and certified results.
**Evidence:** ANV "Anvil share ≤ 1.2 s of the 2 s budget, with Kiln backdating unchanged features"; MEC "Kiln re-runs only features whose inputs changed"; UIX coarse stage "dependent features updated | ≤ 100 ms (contract)"; ING drag specialization "computes the forward slice of that literal"; ANV SSI target "at most 2× OCCT time on transversal cases"; MEC "drawing update after an edit to a 200-feature part in under 1 s", shorter than the rebuild it depends on.
**Fix:** (1) Define Anvil `Interactive` fidelity: the same Portable code with floating-point topology decisions validated after the fact (`check_body` plus Krawczyk verification of traced points), cacheable, never consumed by SignOff checks or releases; SignOff recertifies in the background. (2) State the 2 s target for `Interactive` and add a SignOff target (for example 10 s). (3) Define preview scope: within 100 ms, the dragged feature and as many downstream features as fit, in program order; the rest show stale geometry with a visible boundary. (4) Publish the 200-feature benchmark's operation mix and per-operation budgets, and run a phase 0 spike measuring certified SSI and Boolean cost on ABC face pairs before freezing the targets. (5) Restate the drawing target as "under 1 s after the rebuild completes".

### R2-10 · Major · Targets: CONTRACT, KLN, ANV
**Section:** contract 7.2 (two-stage caching of entity-naming Ops; ruling ING-10 and ANV-5); ANV D-ANV-14; Persistence and versioning
**Problem:** The ruling that the geometric stage is "keyed without OpSite and shared across designs" yields almost no sharing. The key includes input ObjectIds, and the Body hash covers the EntityId section, so after the first named operation of a chain every input differs between designs, and between two calls of the same std feature; only label-free leaf operations share. The ruling also relies on, but does not state, the condition that the geometric core never reads input labels (R2-02).
**Evidence:** contract 7.2; ANV encoding "Sections. Topology tables, geometry pools, `EntityId`s, ..." under one Merkle hash; ANV "each operation runs as a site-independent geometric core, cached without the site and labeled with provisional ids".
**Fix:** Give every Body two identities: `GeomId` (geometry, topology and tolerances in the label-invariant canonical order of R2-02) and the full `ObjectId`. Key the geometric stage by input `GeomId`s; the core returns history in terms of input canonical positions; the relabeling stage, keyed by input `ObjectId`s and the OpSite, maps positions to EntityIds. State in 7.2 that the geometric stage must be label-invariant and reuse oracle ANV-O-LABEL-1. With this, std features called from different designs share every geometric result.

### R2-11 · Major · Targets: ANV, MEC, ING
**Section:** ANV Transform, pattern, mirror; MEC Patterns and mirror; ING Kiln-held values (`.moved(by:)`)
**Problem:** `anvil::transform` keeps EntityIds for rigid motions and reflections, and MEC's `mirror` and Ingot's `move` lower to it. Combining a Body with a moved or mirrored copy of itself, the commonest symmetry idiom (`half + mirror(half, plane.yz)`), or two Instances of one Part in an assembly-level feature, puts identical EntityIds into one Boolean, which fails with `EntityIdCollision` or makes every query on the seed resolve to both copies. Roles also flip meaning under reflection (`side(left)` lands on the right).
**Evidence:** ANV transform row "EntityIds kept: identity for rigid motions, `Modified { aspects: Geometry }` for scaling and reflection"; the separate-id guarantee exists only for `anvil::pattern` ("an original and its mirror copy never share EntityIds"); "Within one Body, a duplicate EntityId fails the operation with `Internal::EntityIdCollision`"; MEC patterns and mirror use "`anvil::transform`, `anvil::boolean` (n-ary)".
**Fix:** Separate placement from copying. A transform whose source value is used again in the program (Ingot knows this from data flow) or that is written as `copy` creates ids `EID(kind, site, role: copy, [source id])` with a new `Copied { from, into }` record that lineage follows only on request (`seed.face(top).copies()`); a motion that replaces the Body in the data flow keeps ids. Reflection records `Mirrored`, so role queries can say `side(left, mirrored: true)`. Assembly-level features prefix ids with the Instance path.

### R2-12 · Major · Targets: ING, MEC, ANV, CONTRACT
**Section:** ING Entities and call sites (Loop indices); Patterns, loops and identity; MEC Patterns and mirror (`skip: [Int]`, `at_points`, `fill`, `by_density`); ANV Rust API (`OpSite`)
**Problem:** `OpSite` uses the positional iteration index by default and keyed iteration is opt-in; patterns name copies and skip instances by index. Patterns driven by geometry (`at_points`, `fill`, `by_density`, `along`) and loops over query results (`for e in body.edges(convex)`) therefore rename every later copy, retarget skip lists and break anchors when one element is inserted or removed. That is positional indexing under another name, contrary to the contract's "No positional indexing".
**Evidence:** ING "Loop indices | The iteration index, or the key of a `keyed` collection"; "`for x in keyed(holes, by: |h| h.label)` uses the key in place of the index" (opt-in); ANV `OpSite { path, indices: Box<[u32]> }`; MEC `skip: [Int] = []`; `by_density` runs Lloyd iterations that move every seed.
**Fix:** Make keys the default. Iteration over `Entity<K>` lists or resolved queries keys by EntityId; transform generators return keyed lists (`linear` keys `(i, j)` from the seed, `circular` the angular index, `at_points` the point's anchor EntityId, `fill` lattice coordinates from a declared origin, `by_density` each seed's initial key before Lloyd steps); plain integer ranges keep integer keys. Replace `skip: [Int]` with `skip: [Key]` and `OpSite.indices: [u32]` with `[SiteKey]`. The language service warns on positional keys over lists whose length depends on geometry.

### R2-13 · Major · Targets: ANV
**Section:** Booleans for every representation pair (D-ANV-20); Performance targets; State of the art (Mesh Booleans)
**Problem:** The chosen method (a global arrangement with indirect predicates on f64, exact classification, rounding with repair) is one to three orders of magnitude slower in published measurements than EMBER, yet its target is "≤ 70 ms on 8 cores, 2× EMBER" for a million triangles. The repair loop has no termination argument. The reason given for rejecting quantized input, EMBER's 15 nm grid, does not apply to a grid at Anvil's own resolution ρ = 2⁻³⁰ of the diagonal.
**Evidence:** EMBER (https://www.graphics.rwth-aachen.de/media/papers/339/ember_exact_mesh_booleans_via_efficient_and_robust_local_arrangements.pdf, opened): 34 ms for 1.2 M triangles on 8 cores; beam case 4.5 ms against 1,556 ms for the floating-point arrangement of Cherchi et al. 2020 and 18,018 ms for Mesh Arrangements; output is a polygon soup with T-junctions. Cherchi et al. 2022 (https://ar5iv.arxiv.org/html/2205.14151, opened): 0.14 s per frame at 200 K triangles, 19.5 s for 21.6 M, and exact-to-float conversion "is still elusive". trueform (https://arxiv.org/abs/2607.15905, opened) claims "up to two orders of magnitude faster" than prior art with valid, watertight output.
**Fix:** Replace the method decision with a phase 0 bake-off on Thingi10K pairs among (a) plane-based local arrangements on integer coordinates of the Body's ρ grid (2³⁰ to 2³¹ cells per diagonal, wider fixed-width predicates) with topology recovery into the half-edge Mesh, (b) trueform's topological aggregation once its license is confirmed, and (c) the current indirect-predicate design; set the million-triangle target from the winner. Bound the repair loop (fixed number of passes, collapse only edges shorter than 2ε, then `PrecisionExhausted`). Lower whole CSG expression trees to one n-ary arrangement so rounding happens once per tree.

### R2-14 · Major · Targets: ANV, MEC, CONTRACT
**Section:** ANV Representation lattice (D-ANV-2), Conversions (Implicit → BRep); MEC Lattices and Field-driven geometry; contract section 5 `Body`
**Problem:** By the lattice, a B-rep part joined with an implicit lattice becomes an `Implicit` Body, which has no faces, edges, attributes or B-rep EntityIds, and in phase 1 converts back only to facet faces. Golden product 2 therefore loses its exact mounting holes, `HoleSpec` attributes, GD&T targets and drawings, although semantic PMI requires exact geometry and post-print machining of interfaces needs exact faces. "Without approximation" holds for the point set, not for the information the Body carries.
**Evidence:** ANV "anything ⊕ Implicit is an Implicit"; conversion table "Implicit → BRep ... 1 (facet), 3 (fitted)"; Implicit "No explicit edges"; CAx-IF PMI recommended practice v4.1 (https://www.mbx-if.org/home/wp-content/uploads/2024/06/rec_pracs_pmi_v41.pdf, opened): "PMI Representation (semantic) data shall only be used when exchanging exact geometry".
**Fix:** Add a phase 1 leaf-preserving conversion: where the active leaf of the Implicit is a B-rep distance leaf, the output face is that leaf's exact face with its EntityId and attributes, trimmed by the certified intersection with the implicit part; only regions where other leaves are active become facet faces. Alternatively allow a cellular Body whose `Material` region carries an implicit fill inside an exact B-rep boundary. Amend the contract's lattice sentence to "the least representation that holds both operands without approximating geometry or dropping B-rep faces that remain on the boundary".

### R2-15 · Major · Targets: MEC, ANV, PLT
**Section:** MEC Solver method (D-MEC-4), Platform notes, Oracles (MEC-O-SK-4), Molded and cast part design (D-MEC-18)
**Problem:** `anvil::solve_constraints` and `anvil::thickness` produce geometry and geometric Fields, which the contract restricts to the `Portable` grade, but MEC specifies faer sparse QR (runtime CPU-feature dispatch and rayon parallelism on by default, no reproducibility statement), says "Fused multiply-add use is fixed per platform class", accepts 1e-12 relative agreement across classes, and computes thickness Fields on the GPU with CPU refinement only near thresholds. Sketch geometry, wall-thickness checks and everything downstream would then differ in bits by ISA or GPU.
**Evidence:** MEC "Blocks above 64 unknowns use sparse column-pivoted QR from faer"; "Fused multiply-add use is fixed per platform class"; MEC-O-SK-4 "agreement within 1e-12 relative across classes"; D-MEC-18 "computed on GPU with exact CPU refinement near threshold values"; faer documentation (https://docs.rs/faer/latest/faer/, opened): `std` adds "cpu feature detection at runtime", `rayon` is "enabled by default", and no determinism guarantee is stated; contract 7.3: `Portable` is "the only grade for geometry".
**Fix:** Solver linear algebra runs on the `kernels` IR with canonical 512-bit lanes and fixed reduction trees; faer is allowed only in a configuration with fixed SIMD width, no runtime dispatch and a fixed reduction order that the determinism suite verifies. Delete the FMA sentence (explicit `mul_add` only in `detmath` and error-free transformations). MEC-O-SK-4 requires bit identity across the canonical class. In D-MEC-18 the GPU only locates candidate thin regions; canonical Field values come from the CPU (`Certified` grade).

### R2-16 · Major · Targets: ING, MEC, ANV
**Section:** ING Sketches and constraints; MEC Solver method (step 4) and Diagnosis
**Problem:** A solved sketch point is returned as `Approx<Point3>` "whose bound comes from the solver's converged residual", but a residual is not a forward error bound: the position error is about ‖J⁻¹‖·‖r‖, large for nearly tangent arcs, nearly parallel lines and near-singular mates. A `Guaranteed` bound derived this way lets `Truth` decide checks wrongly. The convergence rule "below one hundredth of the smallest Anvil entity tolerance" (about 10⁻¹² m for a 0.1 m sketch) also fails on ill-conditioned but valid sketches.
**Evidence:** ING "Reading `s.c.center` after the solve returns `Approx<Point3>`, whose bound comes from the solver's converged residual"; MEC step 4 "Convergence requires the scaled residual below one hundredth of the smallest Anvil entity tolerance involved"; Anvil already certifies roots with Krawczyk elsewhere.
**Fix:** After each well-determined block converges, run a Krawczyk (or Kantorovich) test on the scaled system; the radius of the proven box is the `Guaranteed` bound and certifies a unique solution on the chosen branch. If the test fails, the bound is `Estimated` (an estimate of ‖J⁻¹‖ times the residual) and the report says why. Replace the absolute convergence rule with "residual small enough that the certified box radius is below the smallest entity tolerance", else `IllConditioned { block, condition }` with fixes.

### R2-17 · Major · Targets: ANV, KLN
**Section:** ANV Persistence and versioning (D-ANV-9); Versions and the cache
**Problem:** Bodies are re-encoded in the current encoding version, so a minor version that adds a column with defaults changes the ObjectId of geometrically identical results. Two trusted builders on different releases then write different ObjectIds for one OpKey into the shared cache, downstream keys diverge, and a release that records the results it cites cannot be re-verified bit for bit after an upgrade.
**Evidence:** ANV "A minor version adds optional sections or columns with defaults"; "Writers write only the current version"; "A Body decoded from an older encoding is re-encoded in the current version, so its content hash is an ordinary hash and needs no extra key"; KLN D-KLN-10 note: "A release records the class of every result it cites".
**Fix:** Hash a canonical form that is invariant across minor versions: optional sections and columns equal to their defaults are omitted from the hashed bytes. A major encoding change is a behavior change: it enters item 1 of the OpKey and is pinned in `ingot.lock`, and a writer is kept for every pinned major. Add oracle ANV-O-ENC-2: hashes of the golden corpus are unchanged across minor encoding releases.

### R2-18 · Major · Targets: MEC, ING
**Section:** MEC Tolerancing › Specification model, Two dialects, one model (D-MEC-20); ING GD&T controls as types; ANV Attributes
**Problem:** The GD&T record cannot express constructs both standards use daily, so dialect validation, AP242 export and MEC's own NIST oracle cannot be complete. Missing: pattern and combined-zone specifications (ASME composite frames and simultaneous requirements; ISO 5458 CZ, CZR and SIM), ISO 14405-1 size specification modifiers (two-point, least-squares, maximum inscribed, minimum circumscribed, rank-order sizes, envelope), ISO 2692 material requirements as a governing standard, ISO 1101 intersection-plane, orientation-plane, direction-feature and collection-plane indicators, unequally disposed and offset profile zones, ASME irregular features of size, all-over, translation modifier and statistical tolerancing. Separately, a toleranced face that a later operation splits silently becomes separate zones under the attribute default `Copy`.

**Section:** ING Kiln-held values (`convert`); Approximate values as inputs; ANV Conversions (D-ANV-21)
**Problem:** Ingot wraps converted Bodies in `Approx<Body>` and adds measurement bounds of driving inputs to "the result Body's accumulated ErrorBound", while Anvil keeps per-face conversion bounds in the Body and defines `body.error()` as their maximum. Geometric error then lives in two places with different meanings (representation error against input uncertainty), and `Approx<Body>` makes `Estimated` fits fail as inputs (ING6403) although the Body already records its bound.
**Evidence:** ING "`body.convert(into: Mesh, tolerance: 0.01mm)` returns `Approx<Body>`"; "the bound is recorded in the call's accumulator and added to the result Body's accumulated `ErrorBound`"; ANV D-ANV-21 and `Body::error()`.
**Fix:** `convert` returns `Body`; representation error lives only in Anvil's per-face bounds. Bounds of `Approx` arguments go to an `InputSensitivity` record on the feature call, which variation analysis reads, not into `body.error()`.

### R2-42 · Minor · Targets: ING
**Section:** The query language (Geometric filters)
**Problem:** Writing a filter range as a tolerance (`radius: 3mm ± 0.05mm`) creates a tolerance site, and D-ING-4 records every tolerance a feature receives for PMI and variation analysis, so a selection range can surface as a manufacturing tolerance.
**Evidence:** ING "`radius: 3mm ± 0.01mm` ... a range or `Tol` argument means membership"; D-ING-4 "Every feature call records the tolerances it receives, so variation analysis, dialogs, PMI and `tolerances(x)` can find them".
**Fix:** Filters accept ranges (`radius: 2.95mm..=3.05mm`) or `near(3mm, within: 0.05mm)`; passing a `Tol` to a filter is a compile error whose fix rewrites it as a range.

### R2-43 · Minor · Targets: ANV
**Section:** Intervals without rounding modes; Platform notes (FMA row)
**Problem:** TwoProduct uses `mul_add` "where the CPU has FMA", but Wasm, including every browser build, has no deterministic fused multiply-add instruction, so `f64::mul_add` falls back to a software emulation there and every interval product in the browser becomes much slower than the Dekker path. The stabilization of `next_up` is also left [unverified].
**Evidence:** ANV "TwoProduct uses `mul_add` where the CPU has FMA and Dekker splitting elsewhere"; Rust documentation (https://doc.rust-lang.org/std/primitive.f64.html, opened): `mul_add` "is guaranteed to be the rounded infinite-precision result", which a target without an FMA instruction must emulate; ANV Platform notes: relaxed SIMD is nondeterministic and never emitted.
**Fix:** State that wasm32 builds always use Dekker splitting for TwoProduct and for the division and square-root remainders, and native builds choose FMA by ISA level; both give the same exact error term. Verify the stabilization release of `next_up` and `next_down` and remove the marker.

### R2-44 · Minor · Targets: UIX, ING, ANV
**Section:** UIX From gesture to Ingot edit (ranking rule 1); ING Derivatives
**Problem:** Edit-plan ranking uses derivatives of the dragged quantity with respect to literals, but derivatives through Anvil operations need `anvil::shape_velocity`, which is phase 2, while direct manipulation is phase 1, and ING then falls back to dependence only. UIX does not say what the phase 1 ranking is.
**Evidence:** UIX "The nearest single literal with a non-zero derivative ranks first"; ANV `shape_velocity` "Phase 2"; ING "An Op without a tangent rule makes the derivative fail ... and the UIX ranking falls back to dependence only".
**Fix:** State the phase 1 ranking: provenance first (the literal of the call whose OpSite and role created the dragged entity, for example the extrude distance for an end cap), then IIR dependence distance; derivatives refine the ranking from phase 2.

### R2-45 · Minor · Targets: MFG, ANV
**Section:** MFG Core manufacturing types (`Toolpath` as a wire Body)
**Problem:** A finishing toolpath has millions of moves; storing each move as a B-rep edge with a 128-bit EntityId, a lineage set, history records and a `kinds` map entry multiplies memory and hashing cost by orders of magnitude over a compact polyline.
**Evidence:** MFG `path: Body // wire Body`, `kinds: Map<EntityId, MotionKind> // per path edge`; ANV stores EntityIds, tolerances, lineage sets and history records per entity.
**Fix:** Store a toolpath as a wire Body with one edge per contiguous run of one motion kind, each carrying a `Polyline` or arc-spline curve with per-vertex Field samples; address single moves by (edge EntityId, vertex index), which is not a persistent name. State a size target (for example 10⁷ moves under 400 MB).

### R2-46 · Minor · Targets: ANV
**Section:** Subdivision surfaces (Limit evaluation); Representation lattice
**Problem:** SubD ⊂ BRep is declared a lossless inclusion, but near extraordinary vertices with semi-sharp creases the limit is evaluated by subdivision to a finite depth, because Stam's method does not apply there, so those faces are exact only up to an unrecorded depth-dependent error.
**Evidence:** "Feature-adaptive subdivision to a fixed depth, then patches"; "Stam's evaluation ... does not address creases ... Anvil uses it inside the adaptive scheme only for crease-free neighborhoods".
**Fix:** Give subdivision-limit faces a certified evaluation bound near crease and extraordinary-vertex configurations (the geometric convergence of subdivision gives a computable bound per depth), record it as a conversion bound, and state the inclusion as exact except in those neighborhoods, where the recorded bound applies.

### R2-47 · Minor · Targets: ANV
**Section:** Geometry types (D-ANV-7); Intersections › Building blocks
**Problem:** Procedural geometry can nest without limit (an offset of a blend between an offset and a sweep), and every evaluation, enclosure and cache certification of a nested surface solves the inner definitions again, so cost and enclosure width grow with depth; the draft states no limit or fallback.
**Evidence:** D-ANV-7 "Offset, intersection, sweep, blend and subdivision-limit geometry stays procedural, with exact evaluation plus a cached, certified NURBS approximation"; bounds use "its cached Bézier approximation plus the certified approximation error".
**Fix:** Add a nesting budget per face (for example depth 3): a construction whose inputs exceed it uses its inputs' certified NURBS caches as exact inputs, records their bounds as conversion bounds under the propagation rules of R2-03, and reports `Note::ProceduralFlattened`. State how caches of nested definitions are certified (Taylor models or interval Newton on the defining system) and measure the cost on blend-heavy ABC parts.

### R2-48 · Minor · Targets: MEC, ING
**Section:** MEC Part features; ING Kiln-held values (prelude frames)
**Problem:** The part-feature catalog has no reference geometry beyond the world planes and named `csys` values: no offset plane, plane at an angle, mid-plane between faces, plane through three points, tangent plane, axis of a face or through two points, or construction point on a curve. SOLIDWORKS, NX, Creo and CATIA users rely on these to place sketches, mirrors and patterns.
**Evidence:** MEC part-feature sections (profile, holes, dress-up, patterns, split, direct edits, deform, derived parts, configurations, lattices, machine elements) list none; ING prelude defines "the planes `plane.xy`, `plane.yz` and `plane.xz`"; MEC's drawing example uses `p.csys("mid").plane(yz)`.
**Fix:** Add `std::mech::refgeom` in phase 1: `plane.offset(from, d)`, `plane.at_angle(about: axis, angle)`, `plane.mid(a, b)`, `plane.through(p1, p2, p3)`, `plane.tangent(face, at)`, `axis.of(face)`, `axis.through(p1, p2)` and `point.on(curve, at:)`. Each returns a `CoordSys`-anchored value re-resolved through its queries, with handles for direct manipulation and typed `ResolveError`s.
